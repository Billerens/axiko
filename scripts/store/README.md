# Инструменты автора каталога

Нужны Python 3.10+ и `jsonschema` из `requirements.txt`. Команды ниже выполняются из корня Assi в PowerShell 7; в публичном assi-store замените `scripts/store` на `tools/store`.

```powershell
python -m pip install -r scripts/store/requirements.txt
python scripts/store/validate_metadata.py --index docs/marketplace/examples/index.json
python scripts/store/validate_metadata.py --package docs/marketplace/examples/package.json
python -m unittest discover -s scripts/store/tests -p 'test_*.py' -v
```

## Сборка

`build_catalog.py` читает подпапки с `store.json`, собирает ZIP, внешние манифесты, `index.json` и `build-report.json`. Он не делает сетевых запросов, не публикует релиз, не устанавливает пакеты и не запускает их код. Выходная папка должна находиться вне исходного магазина.

```powershell
python scripts/store/build_catalog.py `
  --store ../assi-store `
  --out ../assi-store-dist `
  --base-download-url https://github.com/Billerens/assi-store/releases/download/v0.1.0 `
  --publisher billerens `
  --licensefile ../assi-store/LICENSE `
  --exclude sparks-ring
```

Для собственного магазина задайте также `--repository-id`, `--repository-title`, `--repository-homepage`, свои `--publisher` и `--base-download-url`. Версия по умолчанию `0.1.0`, меняется через `--version`; она не меняет `game.json.saveVersion`. `--license-id` по умолчанию `UNLICENSED`: сборщик не выдаёт лицензию за автора. Файл `--licensefile` копируется в корень каждого ZIP как `LICENSE`; лицензии сторонних ресурсов должны оставаться рядом с ресурсами.

В папке пакета нужны `store.json`, `README.md`, `module.json` или `game.json` и файлы реализации. `store.json.id` определяет ID, а не имя папки. `target` должен быть `modules/<id>` для модуля либо `modules/games/<id>` для игры. Сборщик отказывается переименовывать старые ID и пути сохранений. Отсутствующий `module.json.id` добавляется только в упакованную копию с записью преобразования в отчёт.

Входной файл берётся из `entry` runtime-дескриптора, иначе используется существующий `ui/index.html`, затем `main.js`. `requires` в исходном `store.json` считается **необязательными интеграциями** и попадает в `optionalDependencies`. Обязательные зависимости общего формата описываются отдельно в `package.json.dependencies`; этот сборщик ориентирован на текущий исходный формат магазина.

Не включаются `store.json`, `tests/`, `data/`, скрытые файлы, `.git/`, `node_modules/` и папки сборок. `README.md` и `LICENSE` находятся в корне, реализация — в `code/`. Старые `_data/assets/` разрешены только как неизменяемые ресурсы и попадают в `assets/`, не в данные пользователя. Иная `_data/` блокирует сборку. Символьные ссылки, исполняемые бинарники, `.min.js/.min.css` и внешние исполняемые скрипты блокируются.

В ZIP фиксированы порядок файлов, время и права; при одинаковых исходных байтах и версиях Python/zlib архивы воспроизводимы. Переносы строк исходников не меняются. При ошибке прежний полный набор артефактов и индекс сохраняются, а новый `build-report.json` получает `ok: false`; публиковать его нельзя. После успешной пересборки нужно заново проверить архивы установщиком.

Проверка известных шаблонов секретов сообщает только путь, строку и тип, не печатает значение. Это предварительная проверка, а не доказательство отсутствия личных данных. Пакеты явно получают `storage.own` и `legacy.full-trust`; `networkDomains` собирается из буквальных HTTP(S) адресов исходников и не является полным анализом сетевого поведения.

## Перед публикацией

1. Проверьте `build-report.json`: `ok: true`, ожидаемые пакеты, исключения, преобразования и замечания по приватности.
2. Прогоните реальные ZIP через установщик Assi в тестовой среде: он дополнительно проверяет содержимое, читаемость, пути, состав и хеши. Python-сборка не заменяет эту проверку.
3. Проверьте работу пакетов на искусственных данных, обновление поверх локальной правки и откат.
4. Опубликуйте ZIP и внешние `*.package.json` по точным URL индекса. Затем поместите проверенный `index.json` в корень HTTPS/GitHub-репозитория.
5. Не заменяйте архив уже опубликованной версии: при изменениях увеличьте SemVer. Клиент отвергает другой SHA-256 той же версии.

В исходном проекте Assi есть дополнительный JVM-прогон всех архивов настоящим установщиком, без выполнения кода пакета:

```powershell
$env:ASSI_STORE_CATALOG_DIST = (Resolve-Path ../assi-store-dist).Path
./gradlew.bat :app:testDebugUnitTest --tests app.assi.StoreCatalogDistributionTest --rerun-tasks --console=plain
```

Он создаёт `catalog-validation.json`, привязанный к SHA-256 индекса. Исходники Assi пока закрыты; этот JVM-тест не входит в публичный магазин. Независимым авторам доступны Python-проверки и проверка плана установки в совместимой сборке приложения.

## Проверка метаданных

`validate_metadata.py` проверяет только локальные JSON. Он не скачивает и не открывает ZIP, не сверяет его реальные размеры/хеши/состав, не исполняет код. Результат — JSON с `ok`, `scope: "metadata-only"` и ошибками по JSON-путям; код выхода 0 означает соответствие формату, 2 — ошибку.

Используются локальные схемы JSON Schema 2020-12 из `docs/marketplace/`, без сети. Нужны UTF-8 без BOM, уникальные ключи, корректный Unicode и SemVer. Для зависимости v1 допускает точную версию или одиночное `>=1.0.0`; клиент проверяет уже установленные зависимости того же источника, не устанавливая их автоматически.

| Ограничение клиента | Значение |
|---|---:|
| Каждый JSON метаданных | 1 МиБ |
| Пакетов в индексе | 2000 |
| ZIP | 5 МиБ |
| Распакованный пакет | 20 МиБ |
| Каждый файл, кроме манифеста | 2 МиБ |
| Файлов с `package.json` | 512 |
| Записей описи без самого манифеста | 511 |

Пути относительные, с `/`, в Unicode NFC. Запрещены обход родителя, скрытые/пустые сегменты, обратные слеши, небезопасные имена и коллизии регистра/Unicode. Обязательны `README.md`, `LICENSE` и входной файл; сумма размеров включает манифест.

`publisher`, `license`, `sourceFormat`, `capabilities` и `networkDomains` — декларации. Ни схема, ни SHA-256, ни отзыв AI не доказывают безопасность или наличие песочницы. Текущий профиль `trustedLegacy` даёт коду доступ к возможностям Assi, включая Java/native.

Примеры в `docs/marketplace/examples` используют `example.org` и нулевые хеши: это образцы метаданных, а не скачиваемые выпуски. `$id` схем тоже использует демонстрационное пространство имён; схемы загружаются только локально.
