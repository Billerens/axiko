# Контракты web-хаба

[English](web-hub.md) · Русский

Хаб — браузерное рабочее место владельца для модулей, игр, чата и Студии. Телефон отдаёт его
через LAN, обычно по `http://axiko.local:8765`, после включения доступа и ввода ключа владельца.
Имя хоста и порт настраиваются.

## Редактируемые файлы и восстановление

Единый заводской исходник — `app/src/main/assets/factory/ui/desk/`:

```text
index.html       hub.css          hub.js
transport.js     client.js
editor-model.js  editor.js        editor.css
```

`Workspace.installFactory` помещает его в `files/axiko/ui/desk/` на устройстве. На чистой
установке заводская и рабочая копии одинаковы. Обновления заменяют нетронутые файлы и
сохраняют правки. LAN обычно отдаёт рабочие файлы, а при их отсутствии — заводские.

`/?factory=1` включает заводской хаб, клиент и общие зависимости `ui/kit` / `ui/vendor`;
`/?factory=0` возвращает рабочие файлы. Безопасный режим тоже использует заводские.
Восстановление не перезаписывает личные файлы: оно даёт рабочий интерфейс для их исправления.

## Навигация и видимость

В обзоре доступны модули, игры, задачи и Студия. Навигация читает `ui/nav.json`, сохраняя
доступ к системным разделам и модулям независимо от изменённого главного экрана. Чат может
оставаться рядом с занятием; узкая вёрстка переключает их. Ctrl/Cmd+K открывает быстрый
переход. Маршруты поддерживают кнопки браузера назад/вперёд.

Переходы агента меняют экран владельца только при включённом Follow. Запрос игры
`axiko.stage` действует на хаб, а не телефон. Видимость следует вкладке браузера и активной
панели: переход в Студию или мобильный чат скрывает игру, а выключение экрана телефона само
по себе не скрывает игру браузера.

Ресурсы редактора загружаются при первом использовании. Модули, навигация, задачи и сведения
об устройстве появляются по готовности независимых запросов. Сохраняйте прежние DOM-узлы и
фокус вместо полного пересоздания интерфейса. Анимации учитывают reduced-motion и скрытие страницы.

## Транспорт и вложенные экраны

Один `AxikoTransport` обслуживает хаб и его фреймы. Вложенные виджеты находят `axikoDesk`
через родительские окна, делят поток событий и открывают экраны в основной области.
Не создавайте отдельный EventSource для каждого виджета.

Транспорт даёт `rpc`, `native`, `call`, `eval`, `subscribe`, `onStatus`, `status`, `login`,
`close`. Сохраняйте коды ошибок, HTTP status и ревизии конфликтов. Таймаут не должен
автоматически повторять запись: первая операция могла уже завершиться.

После переподключения EventSource событие `desk.reconnected` обновляет навигацию, модули
и задачи. Чат сверяет авторитетную историю, сохраняя ввод. Пока ответ идёт, окончательная
сверка ждёт idle. Это не универсальный cursor/replay-протокол. HTTP 401 сохраняет
несохранённую работу и предлагает вход вместо цикла перезагрузок.

Страницы используют `window.axiko`. Браузерные `ui.open`, `ui.back`, `ui.chat`, `ui.stage`,
`draft.open` остаются в браузере. Ресурсы preview и RPC сохраняют контекст черновика;
рабочая страница рядом с черновиком явно сохраняет свой live-контекст.

Готовность приходит по `DOMContentLoaded` или `ui.ready`, не по загрузке необязательных
картинок. Принимайте её только от ожидаемого основного фрейма/документа. Убирайте предупреждение
при готовности или переходе; Retry перезагружает нужный экран. Hash-переход не требует load.

## Студия и ревизии файлов

Файлы имеют независимые вкладки и буферы. Позднее чтение A не меняет B. Сохранение фиксирует
отправленный текст и ревизию; ввод во время запроса остаётся несохранённым. Буферы сохраняются
в этом браузере, конфликт с изменениями телефона требует сравнения.

Редактор принимает UTF-8 до 2 МиБ и меняет только код, не `data/`. Перед рабочей записью
делается снимок, файл заменяется через временный и переименование. Preview сохраняет
черновой контекст; сам хаб открывается отдельной вкладкой, без рекурсивного вложения.
Журнал опрашивается только при открытом разделе.

Операции идут через `POST /__axiko/rpc`:

| Операция | Контракт |
|---|---|
| `desk.read` | `path`, необязательный `draft` → `path`, `text`, `revision`, `size`, `exists`; отсутствующий файл — `code=not_found` |
| `desk.write` | `path`, `text`, `expectedRevision`, необязательный `draft`; создание — `expectedRevision=null`; несовпадение — `code=conflict` и текущая ревизия |
| `desk.status` | Сведения об ассистенте/хосте/устройстве/приложении, протокол, заводской режим и возможности; ключ не возвращается |

Явное `draft:null` означает рабочую папку. При отсутствии поля сервер может определить контекст
по `where`/Referer. Успешная запись вызывает `workspace.changed` с `path`, `revision`, `draft`.

## Проверки

```powershell
node --test scripts/web/editor-model.test.js scripts/web/transport.test.js scripts/web/chat-reconnect.test.js
node scripts/web/editor-browser.cjs
node scripts/web/hub-loading-browser.cjs
node scripts/web/hub-runtime-browser.cjs
.\gradlew.bat testDebugUnitTest assembleDebug
```

Браузерным скриптам нужен Playwright; внешнюю установку задают `PLAYWRIGHT_MODULE` и
`PLAYWRIGHT_CHROMIUM_EXECUTABLE`. Проверяйте широкий/узкий экран, вложенную навигацию,
один общий поток событий, reconnect, ввод, ревизии и заводское восстановление.
`DeskFilesTest` проверяет границы, UTF-8, атомарную запись и черновики.

`live-visibility.cjs` запускается на отдельной QA-установке: он посылает события видимости.
Задайте `AXIKO_HUB_SESSION` (локальный JSON) или `AXIKO_HUB_URL` / `AXIKO_HUB_CODE`, при
необходимости `AXIKO_PLAYWRIGHT_MODULE` / `AXIKO_CHROMIUM_EXECUTABLE`. Ключи не публикуйте.
Нативные `ui_open`, `ui_eval`, `ui_screenshot` адресуют телефон и не проверяют desktop-вёрстку.
