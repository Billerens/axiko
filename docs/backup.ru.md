# Контракт зашифрованной резервной копии

[English](backup.md) · Русский

Копия — один зашифрованный `.axb` с личным состоянием рабочей среды. Сохранение и
восстановление доступны в «Настройки → Система → Резервная копия» через системный выбор
документа Android. Это переносимая копия, в отличие от [истории только кода](snapshot-storage.md).

Реализация: [`app/axiko/backup/`](../app/src/main/java/app/axiko/backup/): `BackupFormat`
(шифрование), `BackupArchive` (опись и проверка), `BackupSwap` (восстанавливаемая замена
каталогов), `Backup` (интеграция с Android).

## Состав

| Часть | Путь в архиве |
|---|---|
| Рабочая папка | `files/axiko/` |
| Данные модулей/игр и базы | `files/data/` |
| Диалоги, задачи и состояние магазина | `files/state/` |
| Черновики | `files/drafts/` |
| История снимков, только по выбору владельца | `files/history/` |
| Настройки SharedPreferences `axiko`, с типами | `prefs/axiko.json` |
| Значения хранилища секретов внутри шифрования копии | `secrets.json` |

Исключены загруженные модели, Linux, каталоги кэша приложения (`cache/`, `code_cache/`) и
`data/.webcache`, cookies / localStorage / IndexedDB WebView, временные журналы восстановления/
установки, загрузки магазина и временные файлы состояния. Символьные ссылки и специальные файлы пропускаются с записью в `skipped` манифеста.

Настройки устройства (`boot_failures`, `widget.*`, `backup.*`), системные разрешения и
привязки виджетов не переносятся. Получатель сохраняет свои настройки резервного копирования.
Ключи AndroidKeyStore никогда не покидают установку: оболочка расшифровывает секреты, копия
шифрует их собственным паролем, а при восстановлении они шифруются ключом нового устройства.
Пароль автоматической копии в саму копию не входит.

Игровые сохранения из `files/data` включены; localStorage держит лишь запасную копию.
Входы на сайты и прочее состояние только внутри WebView через этот формат не переносятся.

## Внешний формат v1

Числа — big-endian. После заголовка в 80 байт идут аутентифицированные кадры.

| Смещение | Байты | Поле |
|---|---:|---|
| 0 | 8 | ASCII `AXIKOBAK` |
| 8 | 2 | Версия формата: `1` |
| 10 | 1 | KDF: `1` = PBKDF2-HMAC-SHA256 |
| 11 | 1 | Шифр: `1` = AES-256-GCM по кадрам |
| 12 | 4 | Число итераций PBKDF2 |
| 16 | 4 | Размер открытого кадра; при записи по умолчанию 1 048 576 |
| 20 | 16 | Соль |
| 36 | 7 | Случайный префикс nonce |
| 43 | 1 | Резерв: `0` |
| 44 | 32 | Проверка пароля |
| 76 | 4 | CRC-32 байтов заголовка 0–75 |

Читатель проверяет magic/version до разбора нового неизвестного расположения, затем CRC.
Допустимы 1…50 000 000 итераций и размер кадра 16…16 777 216. Неизвестный формат и значения
за границами поддерживаемого диапазона отклоняются.

```text
password = UTF-8(NFC(введённые знаки))
master   = PBKDF2-HMAC-SHA256(password, salt, iterations, 32 байта)
key      = HMAC-SHA256(master, "axiko-backup/v1/encrypt")
verifier = HMAC-SHA256(master, "axiko-backup/v1/check")
```

Запись подбирает примерно секунду вычисления на устройстве, от 600 000 до 4 000 000 итераций,
и сохраняет результат. Несовпадение verifier означает неверный пароль; совпавшая проверка
с последующим отказом аутентификации кадра — повреждённые данные.

```text
nonce (12 байт) = префикс (7) || номер кадра с нуля (4) || признак последнего (1)
AAD             = все 80 байт заголовка
кадр            = шифртекст || метка GCM (16 байт)
```

Признак равен 1 только у последнего кадра. Длины не записаны: все кадры, кроме последнего,
занимают `размер кадра + 16` байт, последний — от 16 до этого размера. Последний кадр есть
всегда, даже для пустого текста. Аутентификация номера и признака обнаруживает перестановку,
пропуск/повтор кадров, обрезку и добавление хвоста. Незавершённая запись без подтверждённого
последнего кадра не принимается как полная копия.

## Внутренний архив и опись

После расшифровки получается ZIP. Первым идёт `manifest.json`, затем каталоги (включая
пустые) и файлы в порядке манифеста. Допустимы только `prefs/axiko.json`, `secrets.json`
и содержимое пяти перечисленных корней `files/`. Абсолютные пути, обратные слеши,
управляющие знаки, пустые части, `.` и `..` отклоняются.

Манифест содержит `format: 1`, `kind: "axiko-backup"`, время, сведения о приложении и
устройстве, признак истории, число секретов, `parts`, `dirs`, `files`, `skipped`. ID приложения
информационный; совместимость задают формат и допустимые пути, а не обещание принять любой
исторический вариант хранения.

- У файла есть `path`, `size`, `sha256`, `mtime` (миллисекунды), `x` (исполняемый признак).
- ID частей: `workspace`, `data`, `state`, `drafts`, `history`, `settings`, `secrets`.
  Хеш части считается по `path\nsize\nsha256\n` её файлов в порядке манифеста.
- Размер и SHA-256 каждого извлечённого файла проверяются. Лишний, недостающий или стоящий
  не на месте файл отклоняет архив.
- Настройки: `{ "ключ": { "t": "string|bool|int|long|float|set", "v": значение } }`.
- Секреты: `{ "vault": { "имя": "значение" } }` внутри зашифрованной копии.

## Создание копии

Оболочка дважды спрашивает пароль нативным окном (не меньше восьми знаков); страницы,
JavaScript-движок и модель его не получают. Работа идёт вне UI-потока, события `backup`
сообщают этап и счётчик байт.

Файлы до 8 МиБ сохраняются во временное хранилище и хешируются; большие хешируются и читаются
ещё раз при записи. Рабочая папка и история читаются под замком workspace. Во время установки
из магазина операция отклоняется. Изменившийся большой файл вызывает повтор, не более трёх
попыток; затем возвращается ошибка.

Копия пишется в `files/backup/work-<token>/copy.axb` и целиком проверяется тем же валидатором,
что восстановление, до передачи выбранному документу. Прерванный результат удаляется, если
провайдер документов поддерживает удаление; иначе остаётся непригодный обрывок.

SQLite-базы копируются как файлы, пока модули могут работать. Проверка целостности файлов
не равна согласованному транзакционному снимку базы и её журнала. Выбирайте спокойное время
и проверяйте восстановление модулей с базами.

## Восстановление и отмена

1. Прочитать заголовок и запросить пароль нативным окном.
2. Расшифровать и проверить весь архив в `files/backup/restore-<token>/`; текущее состояние
   пока не изменено.
3. Показать владельцу источник, время, размер, состав и что заменяется. История заменяется
   только при её наличии в копии.
4. После подтверждения сохранить восстанавливаемое прежнее состояние, записать
   `files/backup/restore.json` и перезапустить приложение.
5. До обычного запуска `BackupSwap` ставит каталоги переименованиями, сохраняя прежние в
   `files/backup/before-<token>/`. Настройки загружаются с типами, секреты шифруются ключом
   получателя. Прежний localStorage сохраняется вместе со старым состоянием, чтобы более
   новая запасная копия игры не подменила восстановленное сохранение.
6. Успешный запуск страницы вне безопасного режима завершает удаление прежнего состояния.

Журнал содержит `version`, `token`, `action` (`restore`/`undo`), `phase`
(`dirs`/`settings`/`check`/`cleanup`), `replace`, `at`. Шаги можно повторить после прерывания.
До успешной очистки безопасный режим даёт отмену восстановления в настройках и нативном
меню; прежние каталоги, настройки и секреты возвращаются обратной заменой.

## Автоматические копии

Режимы: выключено, ежедневно, еженедельно. Время по умолчанию — 03:30, хранится три копии.
Папка документов и пароль выбираются системным UI. Пароль остаётся в хранилище телефона
как `backup.password`. Автозапись требует провайдера с сохраняемым доступом к каталогу;
иначе используйте ручной экспорт документа.

Задание `backup.auto` проверяет ежедневно; недельный режим пропускает промежуточные дни.
Имена автоматических файлов — `axiko-backup-YYYY-MM-DD-auto.axb`. Очистка касается только
распознанных автоматических файлов, не ручных копий. Ошибки приходят уведомлением; последний
успех и ошибка видны в настройках.

## Восстановление без приложения и проверки

```powershell
python -m pip install cryptography
python scripts/backup/decrypt.py copy.axb
python scripts/backup/decrypt.py copy.axb --out recovered
python scripts/backup/decrypt.py copy.axb --zip recovered.zip --password-file password.txt
```

Результат содержит личные данные открытым текстом, включая секреты. Храните его и файлы
паролей приватно, вне системы контроля версий. Скрипт проверяет тот же формат шифрования и
описи, что приложение.

`BackupFormatTest` проверяет полный цикл, нормализацию, неверные пароли, повреждения и
перестановку кадров, обрезку, будущие версии, пути и большие файлы. `BackupSwapTest` —
прерывание восстановления/отмены на каждом переименовании и очистку. Образец для отдельного
дешифратора создаётся в `app/build/backup-sample/`.

```powershell
.\gradlew.bat testDebugUnitTest
python scripts/backup/decrypt.py app/build/backup-sample/sample.axb --zip build/backup-check.zip --out build/backup-check --password-file app/build/backup-sample/password.txt
```
