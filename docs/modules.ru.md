# Соглашения для модулей

[English](modules.md) · Русский

Это контракт повторно используемых модулей, а не каталог идей. Актуальные пакеты и их
собственные справки находятся в [Axiko Store](https://github.com/Billerens/axiko-store).
Игры также следуют [контракту общего игрового движка](game-development.md).

## Файлы и точки входа

Модуль — редактируемая папка `modules/<id>/` в рабочей среде:

```text
module.json
main.js                 # необязательный backend Rhino
ui/index.html           # экран, если он нужен
ui/card.html            # необязательная карточка главного экрана
checks.js               # проверки модуля
prompts/                # необязательные инструкции модели
assets/                 # неизменяемые ресурсы пакета
i18n-en.json             # нужен для русских исходных строк интерфейса
```

Минимальный дескриптор экрана:

```json
{
  "id": "my-notes",
  "title": "Notes",
  "description": "Short personal notes",
  "entry": "ui/index.html",
  "autostart": false
}
```

ID должен быть стабильным. Страницы используют `window.axiko`, backend —
`require('lib/axiko')` и CommonJS exports. HTML работает в WebView или web-хабе, `main.js` —
в Rhino. Не переносите браузерные API в backend. У общей игровой симуляции более строгий
поднабор JavaScript, описанный в контракте движка.

`start()` регистрирует события и задания движка. Включайте `autostart: true` только при
необходимости; загрузка должна быть быстрой и изолировать ошибки модуля. Boot также
поддерживает явный список запуска. Скрытая UI-страница не заменяет фоновую службу.

## Данные и обновления

- Изменяемое состояние, базы, загрузки и сохранения — в `data/`, отдельно от кода.
  История возвращает код, но не отменяет запись личных данных.
- При миграции сохраняйте прежние значения и неизвестные поля расширений. Проверяйте
  старые сохранения и настройки, а не только чистую установку.
- Черновики используют общие с приложением `data/`: они отделяют код, но не миграции и
  побочные эффекты.
- Обновления сохраняют локальные правки. Используйте планы и разрешение конфликтов
  магазина, а не прямую замену каталога модуля.
- SemVer пакета и версия схемы сохранений служат разным целям. Следуйте
  [правилам публикации](marketplace/repository-format-v1.md).

## Язык и оформление

Повторно используемые модули и игры обязаны полностью работать по-английски: исходные строки
английские либо к русским приложен полный `i18n-en.json`. Русский и другие языки —
необязательные файлы `i18n-<code>.json`. Для английских исходных текстов `i18n-ru.json` переводит
с английского на русский. Одноразовые личные экраны могут использовать язык владельца.

Динамические строки переводите через `ui.t('Text with {}', value)`. Содержимое владельца и
модели показывайте через `ui.raw(text)`, чтобы перевод не принимал его за текст интерфейса.
Основная витрина магазина тоже английская; переводы следуют
[формату страниц каталога](marketplace/catalog-pages.md).

Обычные экраны приложения используют элементы кита и токены темы (`--bg`, `--surface`, `--ink`,
`--accent` и связанные). Не фиксируйте цвета, ломающие тёмную или светлую тему. Нужны понятные
подписи, клавиатурное управление там, где оно уместно, и вёрстка для узкого телефона и desktop.
Специальные сцены и игры могут иметь своё оформление, если задача этого требует; обычные
элементы управления должны оставаться удобными.

Карточка главного экрана объявляет `home` и необязательный `homeSize` в `module.json`.
Владелец меняет размер и порядок, поэтому страница заполняет рамку и адаптируется по ширине
и высоте. Виджет лаунчера экспортирует `widget()` с `{title, text, open, image}` и обновляется
через `axiko.widget.refresh(id)`. Проверяйте эти поверхности отдельно.

Для обучения используйте `ui.tour.offer`. Текст должен работать без маскота. Кнопки должны
оставаться вне нативной кнопки чата: CSS z-index не перекрывает отдельный слой над WebView.

## Фон, ресурсы и секреты

Фоновые задачи используют планировщик движка; визуальные циклы останавливаются у скрытой
страницы. В хабе видимость следует вкладке браузера и активной панели, а не экрану телефона.
Необязательный сетевой контент не должен задерживать основное работающее состояние модуля.

Пакеты магазина содержат читаемые локальные исходники и ресурсы без удалённого исполняемого
кода. Изменяемые загрузки — в `data/`; сторонние лицензии сохраняйте, личные файлы и ключи
исключайте из архивов.

Запрашивайте секреты через защищённый ввод оболочки, проверяйте наличие и ссылайтесь на них
в поддерживаемых нативных запросах. Не просите ключи в чате и не выводите значения в код
или журналы. Модули всё ещё работают как доверенный код с возможностями приложения;
см. [модель доверия магазина](marketplace/implementation.md).

## Проверки и публикация

Содержательные проверки держите в `checks.js`; чистую/общую логику по возможности тестируйте
на компьютере. Поведение UI и сохранность состояния проверяйте на тестовой установке.
Статический аудит магазина не запускает проверки пакета на личных данных.

[Формат репозитория](marketplace/repository-format-v1.md) задаёт структуру, лимиты, манифесты,
владение обновлениями и конфликты. [Правила проверки](marketplace/review-rules.md) определяют
замечания аудита; язык и оформление — требования качества, а не новые коды нарушений безопасности.

Публичные контракты оболочки — в [native-contracts.md](native-contracts.md).
Подробная справка для работы на устройстве остаётся рядом с реализацией в
[`factory/agent/`](../app/src/main/assets/factory/agent/) и
[инструкциях игровому агенту](../app/src/main/assets/factory/modules/games/AGENT.md).
