# Соглашения разработки игр

[English — основная версия](game-development.md) · Русский

Правила относятся к играм, которые принимает модуль «Игротека». Они дополняют
[соглашения модулей](modules.md), [нативные контракты](native-contracts.md) и
[формат пакетов](marketplace/repository-format-v1.md). Реализация движка находится в
[`factory/modules/games`](../app/src/main/assets/factory/modules/games/), отдельные помощники
описаны в его [`AGENT.md`](../app/src/main/assets/factory/modules/games/AGENT.md).
Правила конкретной игры должны жить рядом с её исходниками и в `guide.md`, а не в дублирующих планах проекта.

## Структура и идентичность

Начинайте с [`engine/template`](../app/src/main/assets/factory/modules/games/engine/template).
Установленная игра лежит в `modules/games/<id>/`; каталог находит там `game.json`.
«Игротека» объявляет вид пакета `game`. Игра не является модулем верхнего уровня и не требует
отдельной регистрации на главном экране.

```text
game.json          ID, версии движка/сохранений, вход, валюты, престиж, ачивки
config.json        числа баланса и метаданные настроек
sim.js             общая детерминированная логика
ui/index.html      кит, движок и скрипты игры
ui/game.js         Game.start(), управление и отрисовка
ui/game.css        стили с поддержкой темы
icon.svg           значок каталога
checks.js          стандартные и собственные проверки
content/*.json     встроенный контент
prompts/*.md       промпты генерации и схемы ответов
fixtures/*.json    сохранения для проверки миграций
guide.md           необязательная подробная инструкция игроку
```

Реальное правило ID задаёт `Core.validId`: 1–96 строчных латинских букв, цифр, точек и дефисов,
начало с буквы/цифры, без `..`, без точки/дефиса в конце. Зарезервированы `engine`, `ui`, `links`,
`daily`, `archive`, `template`. Старые ежедневные игры имеют отдельный формат `daily/YYYY-MM-DD`;
не переименовывайте существующую игру и её сохранения ради нового ID пакета.

Разделяйте SemVer пакета (`store.json.version`), версию движка (`game.json.engine`) и версию схемы
сохранения (`game.json.saveVersion`). Любая правка упакованного файла, включая README и комментарии,
подчиняется правилу неизменяемого выпуска магазина. Неизменяемые ресурсы пакета идут в объявленную
`assets/`, загруженные/сгенерированные ресурсы и кэш — в данные самой игры. Данные владельца
не входят в пакет и не заменяются обновлением.

## Логика переносима и воспроизводима

`sim.js` работает в WebView, Rhino и Node. Используйте общую обёртку заготовки и совместимое
подмножество: `var`, `function`, обычные данные; без `class`, `async`/`await`, синтаксиса ES-модулей
`import`/`export`, spread-вызовов и `for (let/const ...)`. CommonJS `exports` в обёртке заготовки
поддерживаются. Экран может использовать браузерные API,
а логика не зависит от DOM, объектов Android и сетевого запроса. `Core.lint(code,false)` проверяет
общее подмножество.

- Случайные решения — через `ctx.rng` или переданный `rng`, не `Math.random`. Состояние генератора
  сохраняет движок. Случайность украшений не должна расходовать игровой RNG.
- Время логики — `ctx.now` в миллисекундах Unix epoch; `dt` и длительность офлайна задаются в секундах. Не вычисляйте
  прошедшее игровое время по самостоятельному чтению системных часов.
- Цены, рост, доход, пороги и длительности находятся в `config.json`; значения читаются через
  `ctx.config`, `cfg`, `g.config`. Списки контента хранятся данными.
- Неограниченные валюты считают через `Big`. В JSON могут быть числа и строки вроде `"1.5e12"`;
  `Big.of` принимает оба варианта. Валюту, способную превысить `1e15`, не переводят в `Number`
  для арифметики.
- Состояние — JSON-данные, без функций, `Date`, `Map`, `NaN`, `Infinity`. Данные забега идут в
  `state.run`, слоя — в `state.layers.<id>.state`, постоянные данные игры — в `state.meta`.

Основные функции логики:

| Функция | Ответственность |
|---|---|
| `init(ctx)` | Вернуть `{run,layers?,meta?}` для новой игры/забега. |
| `tick(state,dt,ctx)` | Изменить состояние за шаг; учитывать `ctx.mult` в поддерживаемом доходе. |
| `offline(state,sec,ctx)` | Необязательный офлайн по формуле с `{gains?,events?}`. Эффективность офлайна уже учтена движком в `sec`. |
| `prestigeGain(state,layerId,cfg)` | Посчитать награду сброса в валюте слоя. |
| `prestigeHint(state,layerId,cfg,info)` | Необязательная рекомендация `true`/`false`; `null` оставляет подсказку движка по отношению прироста. Меняется подсказка, а не возможность сброса или награда. |
| `bonus(state,layerId,amount,cfg)` | Необязательный предварительный расчёт бонуса при выбранном количестве валюты слоя. |
| `onPrestige(state,layerId,before,ctx)` | Необязательный перенос после сброса движком; `before` — прежнее состояние. |
| `migrate(state,fromVer)` | Перевести прежнюю схему; требуется при поддержке `saveVersion > 1`. |
| `validate(state)` | Вернуть `null` или описание нарушения состояния. |
| `summary(state,cfg)` | Необязательная строка каталога `{line}`. |
| `next(state,now,cfg)` | Необязательные будущие уведомления с ID из манифеста. |
| `procedural(kind,rng)`, `validateStock(kind,item)` | Запасной контент без сети и дополнительная проверка сгенерированных данных. |

`ctx` также содержит связки, запас контента, признак офлайна и поддержку отчёта офлайна.
Экспортируйте действия `buy`, `tap`, `hammer` для экрана и бота вместе, не поддерживайте две реализации.

## Сохранения, миграции и сброс

Движок отвечает за запись, последовательности, копии, согласование офлайна и престиж.
Меняйте состояние через `g.act(fn,options?)`; для важного немедленного сохранения используйте
`{now:true,reason,keep}` или `g.saveNow(reason?,keep?)`. Обычные действия сохраняются с debounce
и предельной задержкой, а также зеркалируются в браузерном хранилище. Не обходите проверку seq
и не подменяйте историю SQLite владельца тестовым состоянием.

При изменении схемы поднимите `saveVersion`, реализуйте миграцию и добавьте fixture прежней версии.
Сохраняйте существующий прогресс и неизвестные поля расширений, если изменение явно не требует
описанного преобразования. Один только новый визуал не требует миграции. Проверяйте результат
настоящим загрузчиком и валидатором. Если установленная игра старее сохранения, движок предлагает
восстановление и режим чтения; не превращайте такое сохранение в новый забег.

Престиж сбрасывает объявленный забег/младшие слои, увеличивает выбранный слой, сохраняет `meta`,
затем вызывает `onPrestige`. Покажите потери, сохранённое и награду. Используйте подтверждение
и резервную копию движка, включая удержание для опасного действия. Свой `prestigeHint` поясняет
выгоду сброса, не меняя его контракт.

## Интерфейс и постепенное раскрытие мира

Создавайте экран через `Game.start({sim,init,render,animate?,help?,root?,id?})`. Используйте
`g.el.top`, `g.el.field`, `g.el.actions`; важные действия должны быть доступны большому пальцу.
Render показывает состояние, а не ведёт второй игровой цикл. Учитывайте `g.readonly` в превью
и восстановлении.

- Переиспользуемая игра обязана полностью работать по-английски. Можно писать исходные тексты
  по-английски; русскоязычной игре нужен полный `i18n-en.json`. Русский и прочие словари необязательны.
- Используйте цвета кита и общие элементы управления, чтобы тема владельца оставалась пригодной.
  Поле может иметь собственную палитру. UI-значки берите из кита/GameIcons, не из эмодзи.
- Цели нажатия — не меньше 44 CSS px (стандартные игровые кнопки — 56), текст читаем,
  подписи и обратная связь явные. Сохраняйте поддерживаемое управление клавиатурой/desktop;
  браузерная игра не должна зависеть от жеста, доступного только телефону.
- Проверяйте узкую/широкую раскладку и resize. Не мешайте системным жестам у краёв; учитывайте
  область нативной кнопки чата при размещении диалогов. Режим экрана выбирает движок —
  не принуждайте desktop к fullscreen.
- Дайте краткую `game.json.help` и при необходимости `guide.md`: управление, валюты, прогрессия,
  последствия сброса и неочевидные механики. Настраиваемые числа подписывайте как значения по умолчанию.

Дополнительная сцена создаётся `Game.scene(...)` один раз в `init`; из `render` ей передаётся
небольшая отдельная модель. Рисование не меняет сохранение, время, RNG и баланс. Различайте
открытое, купленное, активное и пережившее престиж. Мир раскрывается вместе с прогрессом,
а не показывает весь поздний контент сразу.

Агрегируйте большие количества и покупки, ограничивайте эффекты, показывайте итог офлайна вместо
тысяч накопленных событий. `scene.pulse` следует за подтверждённым действием. Удалённые сцены
освобождайте; общий рендерер учитывает видимость, reduced motion и бюджеты кадров/пикселей.
Быстрое игровое поле использует свой поддерживаемый `animate`; украшения следуют реальной камере
и положениям сущностей, а не создают другую версию правил.

## Офлайн, AI и интеграции

Игра работает без сети. Код и ресурсы поставляются локально и читаемо; внешние исполняемые скрипты
и CDN-зависимости не допускаются. Запас контента модели лежит вне сохранения, проходит схему и
проверку значений; промпты, ответы и рисунки являются данными, а не командами исполнения.
Используйте `g.stock.take(kind)` с `sim.procedural` или встроенным контентом при пустом запасе.
Ошибка модели и исчерпанный бюджет не блокируют основной цикл. Соблюдайте настройки генерации,
анимации, сети и расходов владельца.

Используйте проверку рисунков и image-помощники движка. Анимациям нужен неподвижный вариант при
reduced motion. Не вставляйте независимые SVG с совпадающими ID напрямую в общий DOM.

«Пассажир», шаги и ставки подключаются необязательно через манифест. Используйте API и почтовый
ящик движка, не правьте сохранение другой игры. Игра остаётся рабочей без связки или её модуля.
Не копируйте цены и интервалы связок внутрь игры — это настройки общего движка.

## Проверки

Запускайте `checks.js` игры через `engine/checks-kit.js`, добавляя проверки собственных механик.
Стандартный набор проверяет новое состояние, JSON round-trip, прежние fixtures, согласие
12-часового офлайна, темп, отсутствие сети и открытие узкого/широкого экрана. Формула офлайна
должна сходиться с пошаговым расчётом в пределах 1% в стандартной проверке офлайна. Если у игры
своя проверка с другим допуском, укажите его явно: стандартный допуск не является настройкой.

Стандартный idle-бот ожидает первую покупку за 10 секунд и престиж в поездках 3–6. Это исходные
параметры проверки, а не универсальный жанровый дизайн: дайте подходящего бота или `pace:false`
с собственной проверкой темпа, если общий сценарий не подходит.

Проверьте начало, развитое и позднее состояние, успешную/отклонённую покупку, событие, сброс,
перезапуск, возврат из офлайна и прежние сохранения. На устройстве используйте
`module_check('games/<id>')` и `ui_check` с
`modules/games/ui/preview.html?game=<id>&w=both`. Экран проверки отделён от экрана владельца;
`ui_show` нужен только для показа результата. Изменения desktop отдельно проверяются в web-хабе.

Потенциально разрушительные проверки выполняйте на искусственных данных в тестовой установке.
Drafts отделяет код, но не личные данные и нативные разрешения. Магазинная проверка агентом
не должна запускать тесты кандидата в рабочей папке владельца. Сообщайте, что проверено и что нет.
