# Гороскоп по данным

> Шуточный прогноз на день в стиле гороскопа, который сбывается, потому что выведен из привычек владельца. На следующее утро модуль сам проверяет, сбылся ли он.

## Зачем

- Утром прочитать: «Звёзды говорят: вечером вы снова закажете доставку после 22:00 — так было в последние четыре четверга». Посмеяться и, может быть, приготовить ужин заранее.
- Узнать «знак недели» по своим данным, например «Сова в доме Скроллера», и понять, какой была неделя, без графиков.
- Назавтра увидеть «Звёзды не соврали: 2 из 3» и точность звёзд за месяц, 71%. Получается игра «перехитри гороскоп».
- Попросить «что говорят звёзды?» голосом по дороге на работу и услышать прогноз.
- Встроить прогноз одной карточкой в утреннюю сводку, когда она появится.

## Что видит владелец

**Экран `modules/horoscope/ui/index.html`.**

- **Сложенный Fold.** Сверху знак недели: своя нарисованная эмблема-созвездие (точки и линии на SVG) и название. Ниже текст прогноза на сегодня (400–600 знаков), затем «Вчера сбылось: 2 из 3» с отметкой у каждого предсказания и кнопка «прочитать вслух» (`speaker`).
- **Раскрытый Fold.** Слева знак и прогноз. Справа «На чём основано» — каждое предсказание с фактом и источником («4 из 4 последних четвергов: доставка еды после 22:00, Траты»), ниже точность звёзд по неделям столбиками и архив прогнозов.
- Тёмная база, серые карточки, без теней; эмблемы знаков — оригинальные созвездия из 5–9 точек, не астрологические символы и не эмодзи.

**Виджет** (текстовый): «Звёзды на четверг», первая фраза прогноза, «вчера сбылось 2 из 3».

**Уведомление** в выбранное время (по умолчанию выключено): заголовок «Звёзды на сегодня», текст — первое предсказание.

**Голос**: «что говорят звёзды», «какой у меня знак на этой неделе», «сбылся вчерашний гороскоп?». Агент берёт готовый текст через инструмент `horoscope_today` и читает его (`axiko.speech.say`).

**Настройки** (`data/horoscope/settings.json`):

- время прогноза (07:30);
- уведомление вкл/выкл;
- число предсказаний (3);
- минимальная выборка закономерности: дней `n` = 4, совпадений `k` = 3;
- не повторять одно предсказание дольше 2 дней подряд;
- упоминать суммы денег: да/нет;
- упоминать места по именам: да/нет;
- тон: мягкий / ехидный;
- голос чтения: роль `tts` или местный;
- праздник в прогнозе (да), дни рождения близких (нет);
- прогноз читает Питомец (нет), длина его фразы (до 160 знаков);
- ссылка на обои дня (да);
- пороги детекторов, в том числе `holidayDays` = 3, `focusMin` = 25, `focusAttempts` = 3, `focusSplitHour` = 13, `focusSessions` = 4, `focusRatio` = 1,5.

## Как устроено

**1. Сбор закономерностей** — в движке, без модели. Утром `job('horoscope:day', { at: '07:30' })` берёт `days()` из [Здоровья](health.md) за 56 дней и записи общей базы. Детекторы:

| Детектор | Пример предсказания | Как проверяется завтра |
|---|---|---|
| День недели | доставка после 22:00 в `k` из `n` последних таких же дней | `deliveryLate ≥ 1` |
| | шаги выше цели по субботам | `steps ≥ stepsGoal` |
| | экран после 01:00 по пятницам | `lateMin ≥ 15` |
| | визит в одно и то же место по вторникам | визит в это место |
| | кафе по утрам в будни (тег `кафе и рестораны` до 10:00) | такая трата до 10:00 |
| Долг сна | недосып за 3 ночи ≥ 120 мин → «к вечеру потянет в сон, отбой раньше обычного» | `bedtime` раньше медианы |
| Тренд | шаги за 7 дней выше прошлой недели на 15%+ → «звёзды видят разгон» | шаги ≥ медиане |
| Цепочка | цепочка привычки на днях до круглого числа → «12-й день растяжки» | привычка отмечена |
| Близкая цель | до ачивки 1–3 дня ([Ачивки](achievements.md)) | прогресс вырос |
| | фокус от 25 мин в `k` из `n` таких же дней ([Фокус](focus.md)) | сумма минут `focus` за день ≥ 25 |
| | от 3 попыток отвлечься во время фокуса (`blockedAttempts`) | попыток за день ≥ 3; без сессий — `null` |
| Фокус до и после | обычная сессия после 13:00 в 1,5+ раза длиннее, чем до (по 4+ сессии с каждой стороны) → «после 13:00 вы сосредоточены дольше» | сессия этой стороны длиннее обычной другой; без сессий — `null` |
| Календарь | событие сегодня (`READ_CALENDAR`, по желанию) → «встреча в 15:00 затянется» | не проверяется, только для красоты |
| Праздник | праздник сегодня или через 1–3 дня ([Праздничные пасхалки](holidays.md): `occasionToday()`, `upcoming()`) | не проверяется, только для красоты |

Каждое предсказание — `{ id, detector, claim, facts, check, confidence }`, где `confidence = k / n`. Берутся 2–4 лучших по `confidence`, за вычетом повторов последних дней. В подборку обязательно идёт хотя бы одно приятное или нейтральное.

**2. Знак недели** — по понедельникам, тоже без модели. Каждая из 12 «звёзд» получает очки по неделе:

- Сова — экран в ночном окне;
- Жаворонок — подъём раньше 07:00;
- Странник — новые места;
- Домосед — дни только дома;
- Гурман — еда вне дома и доставка;
- Аскет — дни без трат;
- Марафонец — шаги;
- Соня — длинный сон;
- Скроллер — соцсети;
- Монах — дни без соцсетей;
- Транжира — траты сверх бюджета;
- Хранитель — цепочки привычек.

Знак — первая по очкам звезда «в доме» второй: «Сова в доме Скроллера». Пороги очков — настройки.

**3. Текст** — модель роли `horoscope.write`. Подойдёт дешёвая модель или модель на устройстве (Gemma 4 через LiteRT-LM — проверить, как она пишет по-русски); ~1 000 токенов на входе, ~300 на выходе. Промпт требует:

- писать в стиле гороскопа;
- использовать только переданные факты, числа не менять;
- не давать советов о здоровье и лекарствах;
- не упрекать;
- не упоминать суммы и места, если это выключено в настройках.

Ответ проверяется движком: все числа из текста есть в фактах, иначе берётся шаблонный текст. Шаблоны лежат в `modules/horoscope/templates.json`. Без модели модуль работает на шаблонах.

**4. Проверка** — на следующее утро, до нового прогноза. Для каждого вчерашнего предсказания вычисляется `check` по сводке вчерашнего дня: `hit: true | false | null` (`null` — данных нет или день на паузе). Точность за 30 дней: попадания / (попадания + промахи).

**5. Пауза**: в дни паузы (`pause` в общей базе) прогноз мягкий и без предсказаний о шагах, сне, экране и фокусе; праздник остаётся. Например: «звёзды советуют плед и чай».

**Цена**: один запрос к модели в день, около 40 тыс. токенов в месяц на дешёвой модели или ноль на модели в телефоне. Расчёт закономерностей — доли секунды. Батарея — одно пробуждение утром.

## Данные

- `data/horoscope/days/<YYYY-MM-DD>.json` — `{ date, sign, predictions: [{ id, detector, claim, facts, check, confidence, hit }], text, from: 'model' | 'template', model, tokens }`.
- `data/horoscope/signs.json` — знаки по неделям: `{ week, star, house, scores }`.
- `data/horoscope/settings.json`, `modules/horoscope/templates.json`, `modules/horoscope/stars.json` (12 звёзд: название, эмблема-созвездие, очки).
- В общую базу ничего не пишется: прогноз — развлечение, а не факт о жизни.
- В файле дня ещё `pet: { name, mood, phrase, line } | null` — кто читал прогноз.
- Хранение: прогнозы — 1 год, знаки недель — бессрочно (их мало).

## Что нужно от оболочки

Уже есть:

- `job`, `lib/base.js`, сводка дня [Здоровья](health.md);
- `ai.ask({ role, system, prompt })`; модели на устройстве назначаются ролям как провайдер;
- `axiko.speech.say` и `speech.say(text, 'local')`;
- `axiko.notify`, `widget()`;
- `axiko.rows` для календаря (`READ_CALENDAR` объявлено, запросить один раз).

Правка оболочки не нужна.

## Связи

- [Здоровье и привычки](health.md) — главный источник: `days()`, пауза.
- [Траты](spending.md) — доставка, кафе, траты сверх бюджета: `expense` с категорией в `tags` и временем в `at`, как в spending.md (`base.find({ kind: 'expense', tag: 'доставка еды' })`).
- [Игротека](games.md) — сессии игр (`kind: 'play'`) как ещё один детектор дня недели: «по средам вы снова строите метро в «Подземке»».
- [Ачивки за жизнь](achievements.md) — предсказание «до ачивки осталось…»; по желанию ачивка «Перехитрил звёзды» (5 несбывшихся предсказаний подряд, скрытая).
- [Жизнь-RPG](life-rpg.md) — «к субботе — уровень 15».
- [Питомец](pet.md) — по желанию (настройка «Прогноз читает Питомец», выключена) перед прогнозом строка «Прогноз читает Листик (сейчас — спокойный) и добавляет от себя: «…»» — имя и настроение из `state()`, фраза из `phrase` (если короче `petPhraseMax` и без запрещённых слов). Строка показывается на экране и читается вслух вместе с прогнозом, агент получает её в `horoscope_today`. Своим голосом существо не говорит — озвучка та же, что у гороскопа. Запрещённые слова Питомца (`banned`) применяются и к тексту модели.
- [Праздничные пасхалки](holidays.md) — праздник дня (`occasionToday(date)`) или ближайший в `holidayDays` днях (`upcoming(days)`) — одно предсказание «сегодня Новый год» / «послезавтра — Новый год», не проверяется. Траурные (`solemn`) и погодные поводы не берутся; дни рождения близких — только с настройкой, потому что их имена попадут в текст и прозвучат вслух.
- [Фокус](focus.md) — сессии `kind: 'focus'` общей базы (минуты в `amount`, `data.blockedAttempts`): день недели, попытки отвлечься, «до и после 13:00». Без модуля эти детекторы молчат, а проверка даёт `null`.
- [Обои дня](wallpapers.md) — на экране под прогнозом карточка с миниатюрой и названием текущих обоев (`today().current`), нажатие открывает «Обои дня». Только чтение; без модуля карточки нет.
- [Сериал на ночь](bedtime-series.md) — знак недели и сбывшиеся предсказания как деталь сюжета.
- Утренняя сводка — отдельного модуля в списке нет. Если появится, прогноз отдаётся функцией `today()` модуля.

## Этапы

1. **Детекторы и проверка без модели**: день недели и долг сна, шаблонный текст, утренняя проверка «сбылось». Проверка: на подставных днях с доставкой в 4 четверга подряд появляется ровно это предсказание.
2. **Экран**: прогноз, «на чём основано», сбылось/нет, сложенный и раскрытый вид.
3. **Текст от модели** с проверкой чисел и откатом на шаблон.
4. **Знак недели** и эмблемы-созвездия.
5. **Голос, виджет, уведомление**.
6. **Остальные детекторы**: тренд, цепочки, ачивки, календарь.

## Как проверить

- `scripts\check.ps1 -Only "horoscope"`: каждый детектор на подставных днях; проверка `hit` для каждого типа; день паузы даёт `null`.
- Подменить ответ модели текстом с выдуманным числом — модуль откатывается на шаблон.
- На телефоне две недели читать прогноз утром. Спросить себя: смешно ли, верно ли, не повторяется ли. Записать точность звёзд.
- Выключить сеть и назначить роли модель на устройстве — прогноз приходит, время генерации в журнале.
- «Что говорят звёзды» голосом через имя-обращение — агент читает сегодняшний текст, а не придумывает новый.
- Раскрытый Fold с чатом и без — `ui_screenshot`.

## Открытые вопросы

- Тон: мягкий или ехидный по умолчанию?
- Можно ли упоминать траты и суммы? Прогноз могут увидеть другие на экране или услышать вслух.
- Встраивать ли в утреннее уведомление, или только экран и виджет?
- Нужен ли знак недели, или достаточно ежедневного прогноза?
- Использовать ли календарь (встречи) — это уже не про привычки, но делает прогноз живее.

## Риски и ограничения

- В первые 4 недели данных мало — закономерностей нет. Тогда прогноз честно опирается на тренды и цепочки, а детектор дня недели молчит, пока не наберётся `n` одинаковых дней.
- Модель склонна дописывать «факты». Поэтому числа проверяются, а при расхождении берётся шаблон.
- Предсказания о вредном (ночной экран, доставка) могут звучать как упрёк. Фильтр слов как у [Питомца](pet.md) и хотя бы одно приятное предсказание в подборке обязательны.
- Сбывающийся прогноз может закреплять привычку («звёзды сказали — закажу»). Видна точность, и есть ачивка за то, что перехитрил звёзды. Это поворачивает игру в обратную сторону.
