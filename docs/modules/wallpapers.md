# Обои дня

> Каждое утро Axiko находит в открытых источниках фотографию под погоду, сезон и вкус владельца и ставит её на внешний и внутренний экраны Fold и на экран блокировки.

## Зачем

- Утром за окном туман — на телефоне тоже туман над озером, а не вчерашний солнечный пляж. Мелочь, которая делает телефон «живым».
- Владелец задал темы «горы, архитектура, космос»: обои чередуются между ними, не повторяясь месяцами.
- Понравилась картинка — одно нажатие «в избранное»; в выходные Axiko ставит что-нибудь из избранного, а не новое (по настройке).
- Не понравилась — «вернуть вчерашние» и «меньше такого»: тема или автор получают меньший вес, и модуль это помнит.
- Хочется знать, что это за место: в истории у каждой картинки название, автор, источник и лицензия, ссылка на оригинал.
- Тёмная тема Axiko и тёмные обои: модуль предпочитает спокойные, не слишком яркие кадры, на которых читаются часы и значки.

## Что видит владелец

**Утреннее уведомление** (тихий канал, `silent: true`): «Новые обои: Туман над Ладогой. Фото: Анна Петрова, Unsplash». Нажатие открывает экран модуля. Кнопок действий в уведомлении нет: `axiko.notify` умеет только `title`, `text`, `open` (см. «Что нужно от оболочки»).

**Экран модуля** (`modules/wallpapers/ui/index.html`, кит, тёмные серые карточки без теней):

- Раскрытый Fold (ширина 600+): слева большая карточка «Сегодня» с превью обоих кадрирований рядом — узкое (внешний экран, 904×2316) и почти квадратное (внутренний, 1812×2176); под ними название, автор, источник, лицензия, почему выбрано («туман, ноябрь, тема "природа"»). Справа — кнопки: «Вернуть вчерашние», «Другие сейчас», «В избранное» (иконка `star`), «Больше такого», «Меньше такого», «Открыть оригинал» (`link`).
- Сложенный (внешний экран): одна колонка, превью внешнего кадра, те же кнопки списком.
- Вкладки: «Сегодня», «История» (сетка миниатюр `auto-fill, minmax(140px, 1fr)`, нажатие — карточка с «Поставить снова»), «Избранное», «Настройки».
- Пустое состояние до первого запуска: «Обои ещё не выбирались. Нажмите "Подобрать сейчас" — займёт около минуты».

**Виджет** (`widget()`): «Обои дня» / «Туман над Ладогой · Unsplash · 07:00».

**Голос и чат**: «поменяй обои», «поставь что-нибудь с горами», «верни вчерашние», «больше не показывай города» — агент вызывает функции модуля (`axiko.call` / `require('modules/wallpapers/main')`).

## Как устроено

**Расписание.** `start()` модуля регистрирует `job('wallpapers.daily', { at: settings.time }, run)`; модуль добавлен в `starters` в `lib/boot.js`. Это прямой `job`, а не рутина агента: работа детерминированная, агенту в ней думать не о чем, а модель зовётся точечно.

**Шаг 1 — контекст дня.**
- Сезон — по дате и полушарию (широта из геолокации).
- Погода — Open-Meteo без ключа: `https://api.open-meteo.com/v1/forecast?latitude=…&longitude=…&current=weather_code,temperature_2m,is_day`. Код WMO превращается в слово: 0–1 ясно, 2–3 облачно, 45/48 туман, 51–67 дождь, 71–77 снег, 95–99 гроза.
- Тема дня — случайная по весам, с запретом «больше N дней подряд одна тема».
- Праздник — если модуль [Праздничные пасхалки](holidays.md) отметил повод на сегодня, тема дня — повод («новогодний лес», «весенние цветы» к 8 марта).

**Шаг 2 — запрос.** Строка поиска на английском (источники лучше ищут по-английски). Простой вариант без модели — шаблон: `{тема} {погода} {сезон}`, например `mountains fog autumn`. С моделью — роль `wallpapers.query` (маленькая, можно локальную): из контекста и списка «больше/меньше такого» она пишет 2–3 запроса. Ответ JSON `{ queries: [...] }`.

**Шаг 3 — кандидаты.** Из включённых источников по очереди, пока не наберётся `кандидатов на выбор`:

| Источник | Как | Лицензия | Что учесть |
|---|---|---|---|
| Wikimedia Commons | API `action=query`, `generator=search`, `gsrnamespace=6`, `prop=imageinfo` с полями url, size, extmetadata | CC0, CC BY, CC BY-SA, PD — у каждой своя, в `extmetadata.LicenseShortName` | Нужна подпись автора для BY; берём только файлы с явной свободной лицензией |
| Openverse (`api.openverse.org/v1/images/`) | `q`, `size=large`, `aspect_ratio=tall`, `license_type=all` | CC и PD, поле `license` | Анонимный доступ с лимитами; ссылки ведут на исходный сайт |
| NASA APOD (`api.nasa.gov/planetary/apod`) | только для темы «космос», `count=10` | чаще всего общественное достояние | Если в ответе есть поле `copyright` — картинку не берём (не PD) |
| Art Institute of Chicago | `api.artic.edu/api/v1/artworks/search?query[term][is_public_domain]=true` + IIIF | CC0 для public domain | Размер через IIIF; какие размеры отдаются — проверить |
| Unsplash API | ключ владельца (`axiko.secret.ask('unsplash.key', …)`) | Unsplash License | По правилам API: показывать автора и Unsplash, при установке дёрнуть `links.download_location`; размер через параметры `w`, `h`, `fit=crop`, `crop=entropy` |
| Pexels API | ключ владельца | Pexels License | Подпись «Фото: автор, Pexels» |

Обычный поиск картинок по всему интернету (`tools/web_search.js` и сбор `<img>`) по умолчанию выключен: права на такие картинки неизвестны. Включать или нет — решает владелец (см. «Открытые вопросы»).

**Шаг 4 — отсев без модели.** Отбрасываем:
- меньшая сторона оригинала < настройки (2400 px) — на внутреннем экране 2176 px по высоте, на внешнем 2316;
- уже было (идентификатор источника в истории за 365 дней);
- похожее на бывшее: перцептивный хеш dHash (картинка 9×8 в оттенках серого через `Bitmap.createScaledBitmap`, 64 бита) — расстояние Хэмминга ≤ 10 с любым хешем за 365 дней;
- тот же автор за последние 14 дней;
- средняя яркость миниатюры 32×32 выше предела (0,45) — кроме тем, где светлое уместно, по флагу темы.

**Шаг 5 — выбор.** Если включено и у роли `wallpapers.judge` есть зрение (`models.roles` → `vision`), модель получает до 8 миниатюр по 384 px (`ai.ask({ role, prompt, images, json: true })`) и отвечает `{ best: 3, reasons: "...", focus: { x: 0.42, y: 0.55 }, reject: [1, 5] }`. Критерии в промпте: нет текста и водяных знаков, нет крупных лиц и людей в кадре (обои с чужим лицом — странно), спокойная верхняя треть (там часы на блокировке), главный объект переживёт кадрирование в узкую полосу 1:2,56 и в почти квадрат 1:1,2. Без модели — лучший по простой оценке: ближе к целевой яркости, больше разрешение, сильнее контраст по краям в центре.

**Шаг 6 — кадрирование.** Один оригинал режется на два кадра вокруг точки `focus` (от модели, иначе центр): внешний экран 904×2316, внутренний 1812×2176 (на внутреннем мешает шарнир по центру — главный объект смещаем от вертикальной середины на 10% ширины, настройка). Делается в движке через `BitmapFactory` с `inSampleSize` (не грузить 6000-пиксельный оригинал в память целиком) и `Bitmap.createBitmap(src, x, y, w, h)`. Файлы: `data/wallpapers/2026-11-14/cover.jpg`, `inner.jpg`, `thumb.jpg`.

**Шаг 7 — установка.** `WallpaperManager.getInstance(context).setBitmap(bitmap, null, true, which)` с `FLAG_SYSTEM` и/или `FLAG_LOCK`. Как задать отдельно внешний и внутренний экраны Fold — неизвестно, см. «Что нужно от оболочки». Если установка недоступна (нет разрешения) — запасной путь: `WallpaperManager.getCropAndSetWallpaperIntent(uri)` открывает системный экран установки, владелец нажимает «Установить» сам.

**Шаг 8 — запись.** История в SQLite, событие `emit('wallpapers.changed')`, `axiko.widget.refresh('wallpapers')`, тихое уведомление.

**Модели.** `wallpapers.query` — 1 короткий запрос в день (сотни токенов). `wallpapers.judge` — 1 запрос в день с 8 миниатюрами по 384 px. Обе объявлены в `module.json` → `models`, владелец может назначить дешёвую или локальную модель.

**Сеть и батарея.** Раз в день: 3–6 запросов к API (килобайты), 8 миниатюр (~30 КБ каждая), один оригинал (2–8 МБ). Работа идёт ~30–60 с, раз в сутки — на батарею не влияет заметно. При «только Wi-Fi» и отсутствии Wi-Fi в 07:00 — повтор каждые 30 мин до 12:00 (`on('network')` или отложенный `job`), потом день пропускается и ставится картинка из избранного.

## Что нужно от оболочки

Есть сейчас:
- `job`, `on('network')`, `axiko.http.get/download`, `axiko.notify`, `axiko.widget.refresh`, `axiko.store`, `axiko.db`, `axiko.secret.ask/get`, `ai.ask` с `images`, `native('models.roles')` (поле `vision`).
- Rhino с доступом к `android.graphics.Bitmap`, `BitmapFactory`, `android.app.WallpaperManager`, `ACCESS_COARSE_LOCATION` объявлено.

Нужна правка оболочки:
- **`SET_WALLPAPER` в манифесте** — одна строка `<uses-permission android:name="android.permission.SET_WALLPAPER" />`. Разрешение обычное (normal), выдаётся при установке, запрашивать не нужно. Без него `setBitmap` бросает `SecurityException`. Через Shizuku обойти, скорее всего, нельзя: в AOSP нет команды оболочки «поставить картинку обоями» (проверить на телефоне `cmd wallpaper help`).
- **Разные обои на внешний и внутренний экраны Fold.** Это главная неизвестность. Варианты, все — проверить на телефоне:
  1. Скрытые флаги Samsung для второго дисплея в `WallpaperManager` — найти отражением прямо на телефоне: `js_eval` с `java.lang.Class.forName('android.app.WallpaperManager').getDeclaredFields()` и `getDeclaredMethods()`, отфильтровать имена с `SUB`, `COVER`, `FOLD`, `DISPLAY`, `WHICH`. Движок видит непубличные члены.
  2. `WallpaperManager.setBitmapWithCrops(...)` из Android 15+ (кадрирования для разных размеров экрана одной картинки) — есть ли он и доступен ли на One UI 8.
  3. Если ничего нет — один кадр на оба экрана, кадрирование под внутренний с безопасной центральной полосой; владелец узнаёт об этом в настройках модуля честной строкой.
- **Кнопки в уведомлении** («Вернуть», «Нравится») — желательно: расширить `axiko.notify` полем `actions: [{ title, call: 'modules/…/main.js', fn, args }]` через `Notify$ReplyReceiver` или новый приёмник. Без этого — нажатие открывает экран.

## Этапы

1. **Ручная установка.** Манифест + `SET_WALLPAPER`. Функция `setFromUrl(url)` ставит картинку на `FLAG_SYSTEM | FLAG_LOCK`. Проверка: картинка на экране.
2. **Разведка Fold.** Скрипт отражения, поиск способа задать внешний экран отдельно. Записать вывод в этот документ.
3. **Один источник и история.** Wikimedia Commons, отсев по размеру, кадрирование по центру, таблица `history`, экран «Сегодня» и «История».
4. **Расписание и уведомление.** `job` в 07:00, тихое уведомление, виджет.
5. **Повторы.** dHash, запрет авторов и тем подряд.
6. **Погода и сезон.** Open-Meteo, шаблон запроса.
7. **Модель-судья.** Роль `wallpapers.judge`, точка фокуса, кадрирование по ней.
8. **Остальные источники**, ключи Unsplash/Pexels через `axiko.secret.ask`, избранное по выходным, «больше/меньше такого».

## Как проверить

На Galaxy Z Fold5, по шагам, с записью результата:

1. После сборки с `SET_WALLPAPER`: `scripts\eval.ps1` с вызовом `setFromUrl(...)` — обои сменились на внутреннем экране; сложить телефон — что на внешнем; заблокировать — что на блокировке. Снимки `scripts\shot.ps1` в развёрнутом и сложенном виде.
2. Скрипт отражения выводит список полей и методов `WallpaperManager`; пробуем найденный флаг внешнего экрана, проверяем глазами оба экрана.
3. `run()` вручную 10 раз подряд с тестовым флагом «не ставить, только выбрать»: ни одного повтора, у всех кандидатов меньшая сторона ≥ 2400, яркость ≤ 0,45.
4. Кадрирование: открыть `cover.jpg` и `inner.jpg` на экране модуля, главный объект не разрезан шарниром.
5. Перевести время `job` на ближайшие 2 минуты, выключить экран, дождаться — сменилось ли в Doze. Затем в реальное утро.
6. Выключить Wi-Fi при «только Wi-Fi» — повтор по расписанию, в 12:00 — картинка из избранного.
7. `checks.js`: отсев по размеру и dHash на подставных данных, разбор ответа каждого источника по сохранённому образцу (без сети).

## Открытые вопросы

- Можно ли брать картинки с обычного поиска, где лицензия неизвестна (только для своего телефона)? По умолчанию — нет.
- Если раздельные обои на внешний экран недоступны — устраивает ли один кадр на оба?
- Ставить ли обои на экран блокировки или оставить его владельцу (там у Samsung свои часы и виджеты)?
- Люди в кадре: полностью исключить или разрешить, если они мелкие и не главные?
- Регистрировать ли ключи Unsplash и Pexels (бесплатно, нужна учётная запись владельца)?
- Нужна ли подпись (автор, место) где-то на самом телефоне, кроме экрана модуля и виджета?

## Риски и ограничения

- **Внешний экран Fold.** Публичного API для отдельных обоев второго дисплея может не оказаться; тогда раздельные обои не сделать без системных прав.
- **Samsung меняет обои сам.** Если включены «Динамический экран блокировки» или обои из тем Galaxy, установка на блокировку может не держаться или конфликтовать — проверить.
- **Material You / палитра.** Смена обоев перекрашивает системный интерфейс One UI (цветовая палитра из обоев, если включена). Владелец может этого не хотеть — упомянуть в настройках.
- **Лицензии.** Даже у открытых источников бывают ошибки в метаданных; модуль хранит источник и лицензию каждой картинки, чтобы это можно было проверить.
- **Лимиты API.** Unsplash в демо-режиме — 50 запросов в час, Openverse без ключа — ограниченно; раз в день этого хватает, но «Другие сейчас» по 20 раз подряд упрётся в лимит. Кнопка ограничена 5 нажатиями в час (настройка).
- **Память.** Оригиналы до 8000 px — только через `inSampleSize`, иначе `OutOfMemoryError` даже с `largeHeap`.
- **Погода без геолокации.** Нет разрешения на местоположение — нет погоды; модуль просит город вручную.
