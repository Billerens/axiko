# Игротека

> Каталог игр внутри Axiko и общий движок, на котором стоят все игры каталога: сохранения,
> время и офлайн-прогресс, большие числа, престиж, экран одной рукой, звук, запас контента на
> поездку, ачивки и связки с жизнью.

## Зачем

Главный сценарий — залипалки на поездку в метро, где нет сети: короткая сессия на один перегон
(2–3 минуты), длинная — на всю поездку. Каждая игра каталога решает одни и те же задачи: не
потерять прогресс при убийстве приложения, честно посчитать, что накопилось, пока игра была
закрыта, показывать числа вроде 4,5e42, сбрасывать прогресс ради постоянного бонуса. Если это
делает каждая игра по-своему, агент каждый раз пишет заново и с ошибками. Движок делает это
один раз; игра описывает только свою механику и свои числа.

Отдельные игры описаны в `docs/games/*.md` и ссылаются на разделы этого файла по названию
(«Движок: сохранения», «Движок: большие числа» и т. д.) — названия разделов не менять.

## Что видит владелец

**Каталог** — модуль «Игротека» на главном экране (и, по желанию, пункт меню). Экран из кита:

- Вверху полоса связок с жизнью — три короткие плашки: «Поездка: нет» или «В пути 14 мин,
  доход ×2» ([passenger.md](../games/passenger.md)), «Энергия 7» ([steps-fuel.md](../games/steps-fuel.md)),
  «Ставка: 10 000 шагов — пока 6 200» ([daily-bet.md](../games/daily-bet.md)). Нажатие открывает
  лист с подробностями. Связка, которую владелец выключил, не показывается.
- Ниже — карточки игр сеткой `repeat(auto-fill, minmax(160px, 1fr))`, на внешнем экране — один
  столбец строк высотой 64 px. В карточке: значок игры (`icon.svg`) на сером квадрате, название,
  строка состояния из последнего сохранения («+1,2 млн/с · престиж 3»), «был 2 ч назад» и
  метка «накопилось», если игра закрыта дольше часа (настройка `catalog.badgeAfterMin`, 60).
- Разделы: «Играю» (открывались за 7 дней), «Все игры», «На пробу» (пришли из
  [«Игры дня»](game-of-the-day.md)), «Архив» (свёрнут).
- Карточки других модулей, которые тоже игры («Шляпа», «Рисуй — угадаю», «Приключение»):
  раздел «Другие игры Axiko» после «На пробу»; карточка «Игры дня» — над всеми разделами.
  Модуль просит карточку в своём `module.json`: `"games": true` — карточка из `title` и
  `description`; `"games": { "card": "<функция main.js>", "top": true }` — функция отдаёт
  `{ title, text, open, date? }` (`null` — сейчас карточки нет), `top` ставит её наверх.
  Нажатие открывает экран модуля; листа с действиями Игротеки у такой карточки нет.
- Долгое нажатие на карточку — лист: «Закрепить в меню», «Ярлык на рабочий стол»
  (`shortcut.pin`), «Сохранения» (список версий с откатом), «Настройки игры», «Экспорт
  сохранения», «Начать заново» (с подтверждением удержанием), «В архив», «Удалить».
- Кнопка «Новая игра» (значок `plus`) открывает чат с агентом (`axiko.chat()`); пустой каталог
  говорит: «Игр пока нет. Скажите, во что хотите играть, — агент сделает».
- Если игра не прошла проверку «без сети» (см. «Движок: раскладка файлов»), на карточке
  пометка «нужна сеть» и причина в листе.

**Игра** открывается на весь экран (`axiko.stage(true)`), со своей маленькой кнопкой выхода
вверху слева. Общие для всех игр элементы:

- Лист **«Пока вас не было»** при входе после отсутствия (см. «Движок: офлайн-прогресс»).
- Лист **«Престиж»** — что получите, что сбросится, что останется; подтверждение удержанием.
- Всплывающая плашка ачивки внизу экрана, 3 секунды, со значком и названием.
- **Настройки игры** — собираются сами из `config.json` игры (см. «Движок: манифест и конфиг»).

Оформление: тёмная основа, нейтрально-серые карточки (`--surface`, `--surface-2`), без теней
(`box-shadow: none` везде, в том числе в своих стилях игр), никаких эмодзи — только линейные
значки из кита и из `engine/icons.js`. Игра может иметь свою палитру поля, но рамка (верхняя
полоса, листы, кнопки) — из кита, чтобы все игры вели себя одинаково.

## Как устроено

Игротека — модуль `modules/games/`. Сами игры лежат внутри него (`modules/games/<id>/`), поэтому
не появляются отдельными плитками на главном экране: оболочка ищет `module.json` только на
первом уровне `modules/`.

Ключевое решение — **логика игры отделена от экрана и пишется на общем подмножестве JS**,
которое понимают и WebView, и Rhino (ограничения движка из `api.md`: без `class`, `async`,
вызова `f(...args)`, `for (const …)`). Файл `sim.js` игры и общие файлы движка (`big.js`,
`fmt.js`, `rng.js`, `core.js`) подключаются:

- на экране — обычным `<script src>` (кладут объект в `window`), там же идёт вся тяжёлая
  работа: такт, офлайн-прогресс, отрисовка (V8 в десятки раз быстрее Rhino);
- в движке — через `require('modules/games/<id>/sim.js')`: для карточки каталога, времени
  уведомлений и проверок без экрана.

Обёртка, общая для этих файлов:

```js
(function (root, make) {
  var api = make();
  if (typeof exports !== 'undefined') { for (var k in api) exports[k] = api[k]; } else { root.Big = api; }
})(this, function () { /* … */ return { of: of, add: add /* … */ }; });
```

Сохраняет и читает сохранения движок (`modules/games/main.js`, SQLite), экран зовёт его через
`axiko.call('modules/games/main.js', 'save', id, seq, json)`. Связки с жизнью, запас контента и
отчёт об ачивках тоже живут в движке и с экраном игры общаются через «почтовый ящик» игры, а не
правкой её сохранения (см. «Движок: связки с жизнью»).

Тяжёлое (библиотеки, звуки, картинки) лежит в `data/`: снимки рабочей папки перед каждым ходом
агента — полные копии без сжатия, и мегабайты в `modules/` раздували бы каждый снимок.
Загружается это по адресу `https://axiko.local/data/games/...`.

**Без сети — обязательно.** Ничего с CDN во время игры: кэш `WebCache` оболочки владелец может
очистить, и игра в метро сломается. Агент скачивает библиотеку один раз
(`axiko.http.download(url, 'data/games/vendor/<имя>-<версия>.js')`) и подключает свою копию.
Проверка «без сети» (в `checks.js` движка) читает все `.html`, `.js`, `.css` игры и находит
адреса `http(s)://`, кроме `https://axiko.local/`; любая находка — провал. Шрифты — системные
или свои файлы в `data/games/vendor/fonts/`.

Зарезервированные имена, которые не могут быть `id` игры: `engine`, `ui`, `links`, `daily`,
`archive`, `template`. `id` — латиница, цифры и дефис, до 24 символов.

## Движок: логика игры (sim.js)

Функции, которые игра экспортирует (необязательные помечены):

| Функция | Что делает |
|---|---|
| `init(ctx)` → состояние | Новая игра: `{run, layers, meta}` |
| `tick(state, dt, ctx)` | Шаг логики на `dt` секунд; меняет `state` на месте |
| `offline(state, sec, ctx)` → `{gains, events}` | Необяз.: быстрый подсчёт за `sec` секунд формулой |
| `prestigeGain(state, layerId)` → Big | Сколько валюты слоя даст сброс сейчас |
| `prestigeHint(state, layerId, cfg, info)` → `true` / `false` / `null` | Необяз.: своя метка «выгодно» на сбросе; `null` — как у движка |
| `onPrestige(state, layerId)` | Необяз.: что перенести в новый забег |
| `migrate(state, fromVer)` → состояние | Перевод сохранения со старой версии |
| `validate(state)` → `null` или текст ошибки | Своя проверка целостности |
| `summary(state)` → `{line}` | Строка для карточки каталога |
| `next(state, now)` → `[{id, at, text}]` | Необяз.: будущие события для уведомлений |
| `chest(state, rng)` → `{title, items}` | Необяз.: сундук «Пассажира» |
| `procedural(kind, rng)` → элемент | Необяз.: замена запаса, когда он кончился |
| `validateStock(kind, item)` → `null` или текст | Необяз.: проверка элемента запаса |

`ctx` — `{now, config, rng, mult, links, stock}`; `ctx.mult` — множитель дохода от связок на
этот промежуток. Случайность — только из `ctx.rng` (`engine/rng.js`, mulberry32 с зерном в
`state.meta.seed`), иначе офлайн-подсчёт и проверки невоспроизводимы.

Экранная часть пишется как угодно (canvas, Preact из `/ui/vendor/preact.js`, обычный DOM) и
работает через объект игры:

```js
const g = await Game.start({ id: 'subway', sim: window.SubwaySim, render });
g.state; g.config; g.act(state => { /* изменить */ }, { now: false });
g.fmt(big); g.achieve('first-transfer'); g.prestige('city'); g.sfx('buy'); g.buzz('buy');
g.stock.take('events'); g.links.mult(); g.links.spend('rush'); g.on('chest', loot => …);
```

## Движок: такт и время

- Время игры — **настенные часы** (`Date.now()`), а не число прошедших тактов. Состояние хранит
  `lastTick`. Поэтому остановка цикла (экран выключен, приложение свёрнуто, WebView уснул) ничего
  не ломает: при возврате движок досчитывает разницу.
- Логика — фиксированный шаг `1 / tick.hz` (10 Гц для idle, до 60 для экшена) с накопителем;
  отрисовка — на `requestAnimationFrame` отдельно, с потолком `render.fps` (30 на батарее, 60 на
  зарядке; настройки). Idle-игра без анимации рисует только при изменении.
- За один кадр логика продвигается не больше чем на `tick.maxStepSec` (1 с). Разрыв больше
  `tick.gapSec` (5 с) считается отсутствием и идёт через офлайн-прогресс (молча, если меньше
  `offline.minSec`).
- На `visibilitychange` → hidden и `pagehide`: остановить цикл, сохранить немедленно, записать
  `hiddenAt`. На visible: досчитать, при необходимости показать сводку, запустить цикл.
- Часы назад (владелец сменил время, `now < lastTick`): разница считается нулём, `lastTick =
  now`, в журнал игры пишется строка. Часы вперёд — засчитываются, как обычное отсутствие, в
  пределах потолка: это личное приложение, защиты от себя не нужно.
- Фоновая работа в движке (Rhino) не тикает игры: она только считает время ближайших событий
  для уведомлений и показывает «накопилось» на карточке (`sim.offline` на копии, кэш 5 минут).

Проверить на телефоне: приходит ли на страницу `visibilitychange`, когда Axiko сворачивается или
гаснет экран (оболочка не вызывает `WebView.onPause()`). Если нет — цикл крутится в фоне и ест
батарею; нужна правка оболочки (см. «Что нужно от оболочки»).

## Движок: сохранения

**Где.** SQLite `data/games.db` (через `axiko.db('games')`): транзакции SQLite переживают убийство
процесса, а `axiko.files.write` пишет файл без подмены и может оставить его наполовину записанным.

```sql
create table saves (id integer primary key, game text, seq integer, at integer, ver integer,
  reason text, size integer, state text, keep integer default 0);
create index saves_game on saves (game, seq);
```

**Когда.** `g.act(fn)` меняет состояние и ставит сохранение в очередь:

- через `save.debounceMs` (400) после последнего действия, но не позже `save.maxDelayMs` (2000)
  при непрерывных нажатиях;
- каждые `save.everySec` (15) во время игры — копится idle-доход;
- сразу (`{now: true}`) — престиж, сундук, трата запаса или энергии, ставка, а также при
  уходе экрана (`visibilitychange`, `pagehide`).

Вдобавок каждое действие синхронно пишется в `localStorage` (`games:<id>` → `{seq, state}`).
При загрузке берётся запись с большим `seq`; если зеркало новее базы, оно сразу дописывается в
базу. Зеркало — вторая линия, не гарантия: Chromium сбрасывает `localStorage` на диск с
задержкой (проверить на телефоне после `am force-stop`).

**Счётчик `seq`** растёт с каждым сохранением. Движок отклоняет запись, у которой `seq` не больше
последнего сохранённого: так игра, открытая одновременно на телефоне и с компьютера
(«Доступ с компьютера»), не затрёт свежий прогресс старым. Экран, получивший отказ, говорит:
«Игра открыта в другом месте. Перезагрузить?».

**Сколько хранится.** Последние `save.keep` (30) версий игры, плюс по одной за день за
`save.dailyDays` (14) дней, плюс копии «перед престижем», «перед миграцией», «перед офлайн-
подсчётом длиннее часа» с `keep = 1` — их удаляет только владелец. Лист «Сохранения»: время,
причина, строка `summary`, кнопка «Вернуть» (текущее состояние сначала сохраняется копией).

```json
             "applied": ["bet-2026-11-13", "chest-1763050000000"], "stockUsed": ["ev-0193"],
             "stats": {"playMs": 51830000, "sessions": 64, "offlineMs": 290000000, "trips": 21}},
  "card":   "+1,2 млн/с · 3 линии · престиж 3"
}
```

`run` сбрасывается престижем, `layers.<id>` — престижем более высокого слоя, `meta` не
сбрасывается никогда (кроме «Начать заново»). Большие числа — строками (см. «Движок: большие
числа»). Предупреждение в журнале, если состояние больше `save.warnKb` (512 КБ).

**Загрузка и порча.** Порядок: прочитать последнюю версию → `JSON.parse` → `core.validate`
(все большие числа разбираются, нет `NaN`/`Infinity`, `ver` известен) → `sim.validate`. Не
прошла — берётся предыдущая, владелец видит: «Сохранение от 14:02 повреждено, загружено от
14:01». Повреждённая версия не удаляется (для разбора агентом).

**Версии и миграции.** `ver` в сохранении меньше `saveVersion` игры — перед `sim.migrate`
делается копия «перед миграцией». `ver` больше (код откатили в «Истории изменений», а данные
вне снимков остались новыми) — игра не пишет поверх, а предлагает: «Сохранение новее игры.
Вернуть копию, сделанную до обновления?». Каждое изменение формата агент сопровождает файлом
`fixtures/v<N>.json` и проверкой «старое сохранение читается».

**Экспорт и импорт** — JSON в `data/games/exports/<id>-<дата>.json` и «Поделиться»
(`axiko.share` для текста до 100 КБ, иначе путь к файлу).

## Движок: офлайн-прогресс

1. `away = now − lastTick` (не меньше нуля).
2. Меньше `offline.minSec` (60 с) — досчитать молча, без сводки.
3. Засчитывается `credit = min(away, offline.capHours · 3600) · offline.efficiency`; по
   умолчанию потолок **12 часов**, доля **1,0** (ночь плюс дорога). Игра может поднимать потолок
   своими улучшениями (`ctx.capBonusHours`). Если `away` больше потолка, засчитываются
   **последние** `capHours` часов.
4. Засчитанный промежуток режется на отрезки с постоянным множителем по данным связок: в каких
   минутах шла поездка («Пассажир», ×2), когда действовал заряд от шагов. Отрезки идут по
   порядку времени.
5. Каждый отрезок считается `sim.offline`, если игра его даёт (формулой, мгновенно), иначе
   шагами: `steps = min(offline.maxSteps, ceil(sec / offline.stepSec))`, по умолчанию 2000 и
   1 с. Если подсчёт идёт дольше `offline.budgetMs` (250 мс), он продолжается частями с
   полосой «Считаю, что произошло за 9 ч…».
6. Перед подсчётом отсутствия больше часа делается копия сохранения: ошибку в формуле можно
   откатить.

**Лист «Пока вас не было»** (пример):

```
Пока вас не было — 9 ч 41 мин
Засчитано 9 ч 41 мин из 12 ч
  Деньги            +3,72 млрд
  Пассажиры         +1,18 млн
  Из них в поездке  42 мин, доход ×2
  Стройка линии 4 закончена
  Сундук за поездку: 2 вагона, 150 тыс. денег
[ Забрать ]          [ Забрать ×2 — 1 энергия ]
```

Вторая кнопка есть, только если игра объявила трату энергии «удвоить сбор» и связка «Шаги»
включена. Если `away` превысил потолок: «Засчитано 12 ч из 14 ч 05 мин — потолок можно поднять
в настройках игры».

## Движок: большие числа

`engine/big.js`. Число — пара `{m, e}`: мантисса `1 ≤ |m| < 10` (или `m = 0, e = 0`) и целый
порядок `e`, от −9·10^15 до 9·10^15. Точность — 15 значащих цифр (как у `double`), «без потерь»
значит без переполнения в `Infinity` и без зависания на огромных порядках: при разнице порядков
больше 15 меньшее слагаемое отбрасывается.

- Операции: `of`, `parse`, `add`, `sub`, `mul`, `div`, `pow(x, n)`, `sqrt`, `log10`, `cmp`, `gte`,
  `lt`, `max`, `min`, `floor`, `isZero`; объекты неизменяемы; для горячих циклов —
  `addTo(a, b)` без выделения памяти.
- Для idle-игр: `costGeom(base, r, owned, count)` — цена `count` штук при росте `r`;
  `maxBuy(budget, base, r, owned)` — сколько можно купить (через логарифмы, без цикла).
- В JSON — строка `"<мантисса>e<порядок>"`, мантисса до 12 значащих цифр: `"4.512e9"`,
  `"1e0"`, `"-2.5e3"`, `"9.99e1234567"`. Разборщик принимает и обычные JSON-числа. Поля, которые
  не могут перерасти `1e15` (счётчики, уровни), можно хранить числами.
- Игре, которой мало порядка до 9·10^15 («Слои бесконечности»), — своё расширение, описанное в
  её файле; общий формат не меняется.

**Вывод по-русски** — `engine/fmt.js`, `fmt.num(x)`:

| Значение | Вид |
|---|---|
| меньше 10 | до двух знаков после запятой: «7», «2,5», «0,75» |
| 10 – 999 | до одного знака: «12,5», «999» |
| 1 000 – 999 999 | целое с узким неразрывным пробелом (U+202F): «12 345» |
| 10^6, 10^9, 10^12 | три значащие цифры и слово: «1,23 млн», «45,6 млрд», «789 трлн» |
| от `fmt.sciFrom` (10^15) | «4,5e42» — мантисса с запятой, латинская «e», порядок без пробелов |

- Режимы (настройка `fmt.mode`): `words` — по умолчанию, как в таблице; `words-long` — слова до
  10^33 («квадрлн», «квинтлн», «секстлн», «септлн», «октлн», «нонлн», «децлн»), дальше «e»;
  `sci` — «e» с 10^6; `eng` — порядок кратен трём: «45,0e39».
- `fmt.digits` (3) — значащих цифр. В живых счётчиках хвостовые нули не убираются («4,50e42»,
  `font-variant-numeric: tabular-nums`), чтобы строка не прыгала; в статичном тексте убираются.
- Округление: имеющееся — вниз, цена — вверх. Тогда «хватает» на экране всегда значит «хватает».
- Знак минус — «−» (U+2212). Скорость: «+1,23 млн/с». Множитель: «×2,5». Проценты: «15 %».
- Время: «45 с», «3 мин 05 с», «2 ч 14 мин», «3 д 4 ч». Склонение: `fmt.plural(n, 'монета',
  'монеты', 'монет')`.
- Для голоса — `fmt.say(x)`: «одна целая двадцать три сотых миллиона», «четыре с половиной на
  десять в сорок второй».

## Движок: престиж

Слои объявлены в `game.json` (`prestige`) по возрастанию. Слой `k` при сбросе:

- обнуляет `run` (заново `sim.init().run`, затем `sim.onPrestige` переносит что нужно);
- у слоёв ниже `k` обнуляет `currency` и `state`, `count` оставляет;
- начисляет валюту слоя `k`: `sim.prestigeGain(state, k)`, если она не меньше `minGain`;
- `meta` (ачивки, альбомы, статистика, зерно) не трогает.

Формулу даёт игра; рекомендация в `AGENT.md`: прирост — степень от заработанного за забег
(`(earned / threshold)^0.5`) или логарифм, чтобы каждый следующий сброс требовал заметно больше.
Ориентир темпа (настройки игры, проверяются ботом в `checks.js`): первый престиж — за 3–6
поездок, каждый следующий — быстрее предыдущего, пока бонус растёт.

Лист «Престиж»: «Получите 12 опыта инженера: 40 → 52, бонус ×1,40 → ×1,52». «Сбросится:
станции, линии, деньги». «Останется: опыт, улучшения бюро, ачивки». Кнопка срабатывает
удержанием `prestige.holdMs` (1200 мс) — в вагоне трясёт. На кнопке престижа появляется метка
«выгодно», когда прирост не меньше `prestige.hintRatio` (0,5) от уже накопленной валюты слоя.
Перед сбросом — копия сохранения.

## Движок: экран одной рукой и внешний экран Fold

- Внешний экран Fold5 — около 344 CSS-пикселей в ширину, внутренний — около 690 (проверить на
  телефоне через `ui_eval('innerWidth')`). Складывание не перезапускает Activity (в манифесте
  `configChanges` включает размер экрана): приходит `resize`, состояние остаётся.
- Зоны (`engine/game.css`): `.g-top` — валюта и скорость, не больше 20 % высоты; `.g-field` —
  поле; `.g-actions` — главные действия в нижних 40 % экрана, под большим пальцем. Кнопки от
  56 px в высоту, всё нажимаемое — от 48 px; шрифт от 15 px.
- Ширина меньше `layout.narrow` (420): один столбец, второстепенное — в листы снизу. От
  `layout.wide` (600): поле слева, панель улучшений справа.
- Жесты — дальше 24 px от боковых краёв (там системное «назад»). Долгое нажатие (500 мс) —
  подробности. Опасное — удержанием, не двойным касанием.
- Портрет: на внешнем экране движок закрепляет ориентацию
  (`host.activity.setRequestedOrientation(1)` через `axiko.eval`, при уходе — обратно `-1`;
  настройка `screen.portrait`). На внутреннем Android 16 запрет поворота игнорирует (широкие
  экраны, целевой SDK 36) — вёрстка обязана жить и в альбомной.
- Не гасить экран — настройка игры `screen.keepOn` (по умолчанию выключено для idle, включено
  для экшена): флаг `FLAG_KEEP_SCREEN_ON` окна, снимается при уходе.
- Чтобы игра продолжалась на внешнем экране после складывания, владелец один раз включает Axiko
  в системной настройке Samsung «Приложения на внешнем экране» (проверить название в One UI 8).
- `engine/preview.html?game=<id>&w=344` показывает игру в рамке заданной ширины: агент видит вид
  внешнего экрана в `ui_screenshot`, даже когда телефон раскрыт.

## Движок: звук и вибрация

- `engine/sfx.js` синтезирует звуки Web Audio (генераторы и шум с огибающей), без файлов —
  значит, без сети. Набор: `tap`, `buy`, `deny`, `level`, `chest`, `achievement`, `prestige`,
  `alarm`. Игра может добавить свои файлы из `data/games/<id>/assets/`.
- Настройки: `sound.on` (вкл.), `sound.volume` (0,6), `sound.headphonesOnly` (вкл.: в вагоне из
  динамика не играть), `vibro.on` (вкл.), `vibro.scale` (1,0).
- Наушники определяет движок: `AudioManager.getDevices(GET_DEVICES_OUTPUTS)` (проводные, USB,
  Bluetooth A2DP и LE) и подписка `registerAudioDeviceCallback(extend(...))`; изменение уходит
  экранам событием `emit('games.audio', {headphones})`. Беззвучный режим телефона — тишина.
- Вибрация: `tap` 8 мс, `buy` 15, `deny` [10, 40, 10], `achievement` [20, 60, 40], `prestige`
  [60, 40, 120], умноженные на `vibro.scale`. Сделано: настройка `vibro.via` — `auto` (по
  умолчанию) отдаёт узор движку, он играет его `VibrationEffect.createWaveform` (в WebView
  `navigator.vibrate` на части прошивок молчит, а узор движка работает всегда); `web` — через
  `navigator.vibrate`.

## Движок: запас контента на поездку

Пока есть сеть, модель заранее готовит то, что игра покажет в метро: рецепты, этажи, события,
аннотации книг, карточки. Игра объявляет виды запаса в `game.json` (`stock`).

- **Когда пополнять.** Задача `job('games:stock', {every: stock.everyMin})` (120 мин), событие
  `on('network')` с `online: true`, подключение зарядки (`on('power')`). Если «Пассажир» знает
  обычное время поездок, за `stock.beforeTripMin` (60) до него — обязательное пополнение.
  Пополняется вид, у которого неиспользованных меньше `min`, — до `target`, порциями по `batch`.
- **Чем.** `ai.ask({role: 'games.stock', system, prompt, json: true})`. Лимит
  `stock.maxCallsPerDay` (30) на все игры; учёт трат оболочки видит вызовы как обычные.
- **Промпт** (`prompts/<kind>.md` игры + общая рамка движка):

```
Ты пишешь контент для игры «Алхимик». Мир: мастерская, где смешивают стихии и вещества.
Придумай 15 новых рецептов. Правила:
- только оригинальное: никаких названий и персонажей из чужих игр, книг, фильмов;
- названия по-русски, 1–3 слова; без эмодзи;
- ингредиенты — только из списка известных элементов ниже;
- не повторяй уже существующие рецепты (список ниже).
Известные элементы: огонь, вода, земля, воздух, пар, глина, …
Уже есть: пар = огонь + вода; гейзер = пар + земля; …
Ответ — JSON: {"items": [{"a": "…", "b": "…", "result": "…", "text": "одна фраза, до 90 знаков"}]}
```

- **Проверка** каждого элемента: обязательные поля и длины (схема-описание в `prompts/<kind>.md`),
  `sim.validateStock`, повтор по нормализованному названию. Отвергнутое — в журнал игры.
- **Хранение** — `data/games/<id>/stock.json`: `[{id, kind, createdAt, usedAt, item}]`. Игра берёт
  `g.stock.take(kind)` — это чтение файла на телефоне, сеть не нужна; взятое помечается и
  попадает в `meta.stockUsed`.
- **Запас кончился** в метро: сначала `sim.procedural` (игра должна уметь сама), затем, если
  владелец разрешил (`stock.local`, выкл.), модель на устройстве по роли `games.local` с коротким
  промптом в фоне, с меткой «готовится». Игра без нового контента остаётся играбельной.
- Неиспользованное старше `stock.expireDays` (30) удаляется, чтобы запас не устаревал.

## Движок: картинки (engine/art.js)

Все картинки — SVG, поэтому они чёткие на любом размере. Есть три способа:

- **Спрайты по зерну.** Генератор пиксельных спрайтов по маскам: пришелец, корабль, зверь,
  слизень, жук, призрак, механизм, растение, клинок, склянка, кристалл. Маска задаёт, где может
  быть тело; зерно заполняет её; половина отражается; вокруг обводка; тона из одного цвета; лапы
  шагают в два кадра. Одно зерно — один спрайт. Без сети и без затрат, запас бесконечен.
- **Облик от модели** (поле запаса `look`). Модель выбирает форму и цвета под придуманную вещь
  («Ледяной клещ» — голубой жук), рисует генератор. Ответ короткий и дешёвый.
- **SVG от модели** (поле запаса `svg`). Модель рисует значок сама: там, где картинка должна
  изображать именно названную вещь. Движок пересобирает SVG из разрешённых фигур (без скриптов,
  ссылок, стилей, картинок, текста, с цветами только из палитры игры). Плохой необязательный
  значок выбрасывается, элемент остаётся. Правила рисования движок сам добавляет в запрос.

  С разрешения поля (`animate`, `effects`) проходят спокойная SMIL-анимация (цикл не быстрее
  0,3 с) и свечение (`filter` с размытием). Без разрешения они молча выбрасываются.
- **Модель-художник серии** (`engine/series.js`, `"artist"` на виде запаса). Это бесконечный ряд
  картинок по номерам: клинки слияния, ранги, этажи, существа.
  - Игра рисует на каждый номер простую базу (`base(n) → {svg, title?}`).
  - Художник получает базы ближайших номеров и рисунок предыдущего номера как образец. Он
    перерисовывает их по-своему и смело меняет тему.
  - Движок держит рисунки впрок, выше рекорда, и даёт игре настройки «Рисунки»: вкл/выкл,
    анимация, сколько впрок.
  - Экран забирает рисунки увиденных номеров через `g.art.sync` в
    `data/games/<id>/art-<вид>.json`, вне сохранения.

Показ — только как картинка (`<img>`, `<image>`, canvas), не как разметка. При «уменьшить
движение» анимация снимается (`GameArt.still`). Пилоты: «Выживание в волнах» (враги — спрайты,
облик орды дня от модели), «Алхимик» (значки новых элементов от модели) и «Кузница слияний»
(модель-художник клинков).

Всё это доступно и обычным модулям, вне Игротеки, через `lib/art.js`:
- генераторы;
- проверка SVG;
- `art.draw` — разовый рисунок от модели;
- `art.series` — серия в файле модуля.

Агент знает об этом из `agent/api.md`.

## Движок: ачивки

- Игра объявляет ачивки в `game.json` и вызывает `g.achieve(id)` — повторный вызов ничего не
  делает. Время записывается в `meta.achievements`, показывается плашка, звук `achievement`.
- В «Ачивки за жизнь» ([achievements.md](achievements.md)) уходят ачивки с `"life": true`
  (настройка `achievements.share`: `marked` по умолчанию, `all`, `none`). Движок вызывает
  `require('modules/achievements/main.js').grant(item)`, если модуль и функция есть; иначе
  кладёт в `data/games/achievements-outbox.json`, который модуль ачивок забирает при старте.
  Вся передача — в одной функции `report()` движка: если в achievements.md интерфейс иной,
  правится только она.

```json
{"key": "games/subway/first-transfer", "source": "games", "category": "Игротека",
 "title": "Первая пересадка", "text": "Соединили две линии в «Подземке»",
 "at": 1763112000000, "hidden": false, "icon": "modules/games/subway/icon.svg"}
```

- Сессии игры движок записывает в общую базу как факт жизни (настройка `base.sessions`, вкл.):
  `base.add({kind: 'play', title: 'Подземка', amount: 23, unit: 'min', source: 'games',
  data: {game: 'subway', trip: true}})` — при уходе с экрана, если сессия длиннее минуты.
  Это видят «Тайная жизнь телефона», «Гороскоп» и ачивки («Сто часов в метро»).

## Движок: связки с жизнью

Три связки — [«Пассажир»](../games/passenger.md), [«Шаги — топливо»](../games/steps-fuel.md),
[«Ставка на день»](../games/daily-bet.md) — живут в движке (`modules/games/links/*.js`) и
работают без открытой игры. Игра подключает их строкой в `game.json` (`links`), владелец
выключает любую связку для игры в её настройках.

- **Множитель.** `g.links.mult()` — произведение действующих множителей сейчас (поездка ×2,
  заряд прогулки ×1,5). Игра умножает на него доход. Для офлайна движок отдаёт отрезки времени
  с множителями (см. «Движок: офлайн-прогресс», шаг 4).
- **Энергия.** Общий на все игры запас из шагов. `g.links.energy()` — сколько есть;
  `g.links.spend(id)` — списать цену траты `id` из `game.json`; ответ `{ok, left}`, эффект
  применяет игра. Энергия — бонус, не допуск: игра без неё полностью играбельна.
- **Почтовый ящик.** Движок никогда не правит сохранение игры. Начисления и списания связок
  кладутся в `data/games/<id>/inbox.json`:

```json
[{"id": "bet-2026-11-13", "at": 1763071200000, "from": "bet", "op": "add",
  "currency": "money", "amount": "2.4e9", "reason": "Ставка выиграна: 10 000 шагов"},
 {"id": "chest-1763050000000", "at": 1763050000000, "from": "passenger", "op": "chest",
  "reason": "Поездка 34 мин без сети"}]
```

  Экран применяет записи при загрузке и каждые 30 с: `add`/`take` — по `path` валюты из
  `game.json` (без кода игры), `take` — не больше, чем есть; `chest` — через `sim.chest`, затем
  событие `chest`. Применённые `id` хранятся в `meta.applied` (последние 500), повтор не
  применяется. Ящик чистится от записей старше 30 дней, которые уже применены.

## Движок: уведомления

По умолчанию игры молчат: залипалка не должна звать. Владелец включает уведомления игры в её
настройках (`notify.<id>`), есть тихие часы `notify.quiet` (23:00–08:00). При сохранении на
уходе движок спрашивает `sim.next(state, now)`, берёт ближайшее включённое событие в пределах
суток и ставит `job('games:notify', {at: 'ЧЧ:ММ'}, fn)`; `fn` снимает задачу (`unjob`), шлёт
`axiko.notify({title, text, open: 'modules/games/<id>/ui/index.html'})` и ставит следующее.
Точность — минута; разовой задачи «в момент X» у оболочки нет (см. «Что нужно от оболочки»).

## Как агент делает новую игру

1. Владелец говорит: «Сделай игру, где я развожу грибы в подвале». Агент читает
   `modules/games/AGENT.md` (одна строка в `agent/handbook.md` отсылает туда).
2. Расспрос формой `ask_owner`, один-два круга: ядро на 10 секунд, на перегон и на поездку;
   нужен ли престиж и что он даёт; какие связки; вид (абстрактный, пиксельный, схемы).
   Вариант агента отмечен.
3. `plan_propose`, затем копия `engine/template/` в `modules/games/<id>/`, заполнение
   `game.json`, `config.json`, `sim.js`, экрана, `icon.svg` (контур 24×24, как у модулей),
   `checks.js`. Числа — в `config.json`, контент — в `content/*.json`.
4. Проверки до ответа владельцу (`module_check('games/<id>')` — проверить, что инструмент
   принимает путь с косой чертой; иначе `games` прогоняет все игры):
   - бот без экрана в Rhino: три дня по две поездки по 25 минут и ночи между ними —
     темп из `config.json` (первая покупка за 10 с, первый престиж за 3–6 поездок);
   - офлайн 12 ч формулой и шагами дают одно и то же с точностью 1 %;
   - сохранение туда и обратно, `validate`, миграции из `fixtures/`;
   - экран открывается без ошибок в `preview.html` при 344 и 690; нет адресов `http(s)://`.
5. `ui_screenshot` обоих видов, короткий ответ владельцу: как играть, что даёт престиж.
6. Правки игры, в которую владелец уже играет, — в черновике (`draft_begin`), если меняется
   формат сохранения или баланс. Новый контент — по возможности данными (`content/*.json`).

## Что нужно от оболочки

Есть и используется: `axiko.call`, `axiko.eval`, `axiko.on`, `axiko.stage`; в движке `axiko.db`,
`axiko.files`, `job`/`unjob`, `on('network' | 'power' | 'screen' | 'headset')`, `emit`,
`axiko.notify`, `ai.ask` с ролями из `module.json`, `native('shortcut.pin')`, `host.activity` и
`ui(fn)` для ориентации и флага экрана, `extend` для `AudioDeviceCallback`.

Правки (по важности):

1. **Видимость экрана.** Проверить, приходит ли `visibilitychange` при сворачивании и гашении.
   Если нет — `MainActivity.onPause/onResume` вызывают `page.web.onPause()/onResume()` для экрана
   модуля или шлют событие `app.visible {on}` всем страницам (несколько строк Kotlin).
2. **Разовая задача.** `job(key, {once: ms}, fn)` в `Jobs.kt`: сейчас уведомление к точному
   времени собирается из `{at}` и `unjob`.
3. **Вибрация узором** — правка `lib/axiko.js` (не Kotlin): `vibrate([ms, …])` через
   `VibrationEffect.createWaveform`.
4. **Строка в `agent/handbook.md`**: «Игры для Игротеки делайте по `modules/games/AGENT.md`».

Проверить на телефоне: `navigator.vibrate` в WebView; ширины экранов Fold5; переживает ли
`localStorage` `am force-stop`; ориентация на внешнем экране; задержка Web Audio.

## Как проверить

На Galaxy Z Fold5, обе половины экрана:

- **Убийство.** 20 покупок подряд, `adb shell am force-stop` сразу после последней. После
  запуска потеряно не больше последних 0,4 с. Повторить, убив во время престижа: либо до, либо
  после, без полусостояния.
- **Порча.** Испортить последнюю строку `saves` через `js_eval` → игра грузит предыдущую и
  говорит об этом.
- **Без сети целиком.** Очистить кэш библиотек (`webcache.clear`), включить режим полёта,
  перезапустить Axiko: каталог, каждая игра, звук, запас — работают.
- **Время.** Перевести часы на 5 ч вперёд → сводка «5 ч». На час назад → без отрицательного
  дохода. Не открывать 14 ч → «Засчитано 12 ч из 14 ч».
- **Экран.** Игра открыта, экран погашен на 10 минут → при разблокировке сводка за 10 минут;
  батарея за эти 10 минут почти не тратится (`dumpsys batterystats` через Shizuku).
- **Складывание** посреди игры: без перезагрузки, раскладка меняется, прогресс на месте.
- **Одной рукой** на внешнем экране в вагоне: все главные действия — большим пальцем, без
  перехвата телефона.
- **Две копии.** Игра открыта на телефоне и с компьютера → старая копия получает отказ.
- **Числа.** Проверки `big.js` и `fmt.js` таблицей: `fmt.num(1234567)` = «1,23 млн»,
  `fmt.num(Big.parse('4.5e42'))` = «4,5e42», цена 999,4 показывается «1 000».
- **Батарея.** 30 минут idle-игры на внешнем экране при 30 кадрах — расход заметно меньше, чем
  у видео той же длины.

## Открытые вопросы

- Числа: «слова до трлн, дальше 4,5e42» — или слова дальше (квадрлн, квинтлн)?

- Энергия от шагов — только бонус (как предложено) или где-то и допуск?

## Риски и ограничения

- Поведение WebView в фоне не проверено: без правки оболочки цикл может тратить батарею.
- `localStorage` не гарантирует запись при убийстве; главная защита — частые сохранения в SQLite.
- Rhino медленный: тяжёлый подсчёт офлайна — только на экране, в движке лишь `sim.offline`
  формулой и `sim.next`.
- Агент, меняющий игру, может сломать старые сохранения — отсюда копии, `fixtures/` и проверки.
- Откат кода в «Истории изменений» не откатывает данные — отсюда правило «сохранение новее игры».
- Точность больших чисел — 15 значащих цифр; для экономики idle-игр этого хватает, для точных
  счётчиков — нет (их хранить обычными числами).
- Контент модели может повторяться или быть скучным — фильтр повторов и процедурная замена.
