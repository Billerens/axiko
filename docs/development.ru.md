# Соглашения по разработке

[English](development.md) · Русский

Начните с [архитектуры](architecture.md), [соглашений для модулей](modules.md) и
[контракта разработки игр](game-development.md). Здесь описана работа с оболочкой и
заводской рабочей папкой. Примеры выполняются в PowerShell 7 из корня репозитория.

## Сборка и установка

Нужны JDK 17 или новее и Android SDK platform 36. Один раз загрузите библиотеку распознавания:

```powershell
scripts\fetch-libs.ps1
.\gradlew.bat assembleDebug
adb -s <device> install -r app\build\outputs\apk\debug\app-debug.apk
```

`-Pphone` оставляет только ARM64. Обычная debug-сборка также содержит x86_64 для эмулятора.
`-PcleanPreview` создаёт отдельную установку `app.axiko.cleanpreview` с результатом в
`build/clean-preview/`; обычное приложение владельца при этом не очищается.

Обновление должно иметь тот же сертификат подписи, что установленное приложение. Держите
ключи подписи вне репозитория. Не решайте несовпадение подписи удалением приложения с
личными данными. Для намеренного переезда в другую установку или на другой телефон
используйте [резервную копию](backup.md) с учётом её исключений.

Публичный APK для ARM64 собирается командой `.\gradlew.bat assembleRelease -Pphone`.
Релизная сборка сверяет сертификат подписи с закреплённым в `app/build.gradle.kts`.
При необходимости укажите путь к подходящему хранилищу ключей через
`-PaxikoReleaseKeystore=<локальный путь>`. Для debug-сборок подходит локальный ключ
разработчика.

Для каждого стабильного релиза увеличивайте Android `versionCode` и задавайте
`versionName` в соответствии с версией в теге GitHub, например `v0.3.2`.
Загрузите APK под именем `axiko-0.3.2-arm64-v8a.apk` и добавьте английские и русские
заметки о выпуске в GitHub Releases. Axiko использует этот файл и его SHA-256
при проверке и загрузке обновления.

Встроенная сборка PRoot требует страницы памяти 4 КиБ; на устройствах с 16 КиБ настройки
показывают ограничение. Shizuku — отдельное приложение, которое запускает владелец.
Не считайте привилегированные операции и разрешения Android заранее доступными.

## Контракты кода и данных

- Нативный код — в `app/src/main/java/app/axiko/`, исходные редактируемые файлы — в
  `app/src/main/assets/factory/`. Исправлению рабочего интерфейса соответствует такая же
  правка заводской версии.
- Личное состояние хранится в `data/`, отдельно от версионируемого кода. Откат рабочей папки
  не возвращает данные. Миграции должны сохранять прежние значения и путь восстановления.
- Разделяйте браузерный JavaScript и код Rhino/общей симуляции. Браузерные API не должны
  незаметно становиться требованиями к движку.
- Сохраняйте [нативные контракты](native-contracts.md), публичный bridge, проверки ревизий и
  планы магазина. Не обходите конфликты перезаписью текущих файлов или каталогов модулей.
- Содержимое пользователя и репозитория — данные, а не HTML или исполняемые инструкции.
  Ключам не место в исходниках, контексте модели, выводе команд и журналах.
- Общие элементы приложения используют токены темы и перевод кита. Публичные интерфейсы
  модулей и витрины обязаны полностью работать по-английски; русский и другие языки —
  дополнение. См. [соглашения для модулей](modules.md).
- Изменение файла, включённого в пакет, требует новой версии по
  [формату репозитория](marketplace/repository-format-v1.md). Версия пакета и версия схемы
  игровых сохранений служат разным целям.

## Документация

Основной язык — английский: `docs/<topic>.md`. Дополнительная русская версия —
`docs/<topic>.ru.md`. Сначала давайте ссылку на английский, русский — отдельной ссылкой.
Требования версий должны совпадать. Имена API, ключи схем, примеры кода и машинные схемы —
общие контракты, а не отдельные локализованные реализации.

После переноса или правок проверяйте локальные ссылки и якоря разделов:

```powershell
python scripts/docs/check_links.py
```

## Проверки

Запускайте проверки изменённого поведения, затем проверяйте настоящий runtime нужного
интерфейса. Браузерная заглушка не заменяет Android-интеграцию, а тестовый провайдер не
оценивает рассуждения реальной модели.

| Назначение | Команда |
|---|---|
| JVM-тесты | `.\gradlew.bat testDebugUnitTest` |
| Проверки Android-оболочки | `scripts\check.ps1 -Serial <device> [-Only "часть названия"]` |
| Скрипт движка на выбранном устройстве | `scripts\eval.ps1 script.js -Serial <device>` |
| Снимок устройства | `scripts\shot.ps1 out.png` (проверьте параметр устройства перед запуском) |
| Web-транспорт, редактор и чат | `node --test scripts/web/transport.test.js scripts/web/editor-model.test.js scripts/web/chat-reconnect.test.js` |
| Изолированный тестовый провайдер | `node scripts/mock-llm.mjs` |
| Проверка переводов | `python scripts/i18n.py` |
| Метаданные магазина и инструменты авторов | [scripts/store/README.md](../scripts/store/README.md) |

Браузерным тестам `scripts/web/` нужен Playwright; настройка — в [web-hub.md](web-hub.md).
Синтетические события, созданные тестом модули и тестовые модели запускайте на эмуляторе или
отдельной QA-установке. Артефакты храните в игнорируемом `build/`. Не публикуйте личные
бэкапы, логи, снимки экранов, модели, `.env`, локальные настройки SDK и ключи подписи.

Перед обновлением личного телефона сохраните восстанавливаемое состояние и проверьте
устройство, пакет и подпись. После — установленную сборку и затронутые настройки/данные.
Успешная сборка сама по себе не подтверждает успешную установку.

## Встроенные лицензии и исходники

Сохраняйте сторонние уведомления и соответствующие исходники вместе с бинарниками. Для
встроенного PRoot и загрузчиков приложены исходники и сборочные скрипты поставляемой
Android-сборки, включая talloc. См. [уведомление PRoot и инструкцию](../app/src/main/assets/licenses/proot/README.md)
и [архив исходников](../app/src/main/assets/licenses/proot/proot-android-0.15-corresponding-source.tar.gz).
Уведомления зависимостей — в [`assets/licenses/`](../app/src/main/assets/licenses/). Очистка
документации не должна удалять эти лицензии и обязательные исходники.
