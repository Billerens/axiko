# Чистая установка рядом с основной Assi

Для проверки заводского состояния можно собрать отдельный пакет без доступа к пользовательским данным основной установки:

```powershell
$env:JAVA_HOME = 'C:\Program Files\Android\Android Studio\jbr'
.\gradlew.bat assembleDebug -PcleanPreview -Pphone
```

- Пакет: `app.assi.cleanpreview`.
- Название в Android: «Assi · чистая».
- APK: `build/clean-preview/app/outputs/apk/debug/app-debug.apk`.
- Activity: `app.assi.cleanpreview/app.assi.MainActivity`.

Без `-PcleanPreview` сохраняются обычный пакет `app.assi`, название Assi и обычный каталог сборки. Данные, настройки, WebView и authority провайдера у чистой установки отдельные. В неё нельзя копировать настройки или данные основной установки, если нужна проверка первого запуска.

На Fold проверена новая установка: один штатный модуль Игротеки, ноль установленных игр, один основной агент, ноль провайдеров и сообщений. Модели не загружены. Первый экран предлагает подключить модель. Для показа web-хаба только у чистой копии включён LAN на отдельном порту 8766 с именем assi-clean; основная установка использует 8765.

После демонстрации по просьбе владельца пакет app.assi.cleanpreview удалён с Fold, основная app.assi открыта снова. В основной установке проверены 20 модулей, 6 агентов и 3 провайдера; восстановление из архива не потребовалось.

Доступ к уведомлениям для демонстрационной установки отклонён; разрешения основной Assi и роль системного ассистента не изменялись. На первом запуске Android показал диагностическое сообщение о 16-КБ выравнивании нативных библиотек debug-сборки; оно закрыто обычной кнопкой «ОК». Сам пакет использует существующий pageSizeCompat. Проверка и обновление этих нативных библиотек — отдельная задача.

Для резервного копирования существующей установки недостаточно снимка Workspace: он не включает данные модулей, настройки и историю чатов. Нужны внутренние хранилища приложения, установленный APK и сведения о системных разрешениях. Скачиваемые веса моделей и их вычислительный кэш можно исключить, сохранив настройки и список файлов. При активной роли VoiceInteractionService Android способен перезапустить Assi после force-stop; для согласованного снимка нужно проверять фактическое отсутствие записей, а не только успешный результат команды остановки.
